**Status:** finalized (Christian, 2026-07-19) — all recommendations adopted, with one amendment:
**LM Studio has full parity with Ollama and is the designated primary smoke-test target.**
**Date:** 2026-07-19
**Baseline:** v3.2.3, main `aa2440b` (post-#61 routing + v3.2.x cost-aware defaults; v4.0/v4.1 specs approved, not yet shipped)
**Inputs:** `docs/ROADMAP.md` v4.2 entry (locked 2026-07-18); enhancement-council proposals
A1/B3/C1/D1/E1 (local providers — five lenses' #1) + C2 (`init --claude`), C8 (doctor after
wizard), C10 (docs for `spend`/`doctor`/`key`); prior MVP spec
`2026-06-24-local-ollama-provider-mvp-design.md`; routing contract

**Release:** ships as **v4.2.0** (minor — additive config + commands; no breaking surface).

## 1. Goal

Run sidecars, fanouts, and council seats on **local / OpenAI-compatible endpoints** — Ollama,
LM Studio, vLLM, and any self-hosted or air-gapped OpenAI-compatible server — at zero marginal
cost, privately, offline. A user-defined provider gets: a config entry (`baseURL` + `type`), a
route class the #61 gateway router understands, live model listing, a real **$0 pricing tier**
(spend ledger, budget gates, and the key-add picker all handle it as priced-at-zero, not
"unpriced"), wizard/CLI add flows, and a doctor reachability check.

Riding along as the "easy to start" polish: **`amicus init`** (C2 — on-demand skills + MCP
registration for plugin-channel/`--ignore-scripts` installs), **doctor at the end of the setup
wizard** (C8), and **real docs for `spend`/`doctor`/`key`** (C10).

## 2. Non-goals

- **Bedrock / `type: 'aws'`** — out of scope; the `type` discriminator and provider-entry shape
  must admit it later (carried forward from the MVP spec).
- **Auto-`ollama pull`** or any model lifecycle management on the local server.
- **Per-model tool-capability gating** — small local models are unreliable tool users
  (MVP research); v4.2 advertises local seats for chat/council prose. Capability detection via
  Ollama `/api/show` is a tracked follow-up, not in scope.
- **Curated support for metered OpenAI-compatible clouds** (Groq, Together, Fireworks) — they
  *work* through the generic `openai-compatible` type with a bearer, but get no presets, no
  curated pricing, no aliases. Their pricing stays whatever the user configures (default $0 is
  wrong for them — documented).
- **Secret-store backends / org policy** (v5.0), **observability** (v4.5), **GUI workspace** (v4.6).
- No changes to council semantics, the #61 descriptor grammar, or the 5-vendor built-in registry.

## 3. Relationship to the 2026-06-24 Ollama MVP design

That spec predates the #61 rearchitecture (it targeted v1.2.0's `validateApiKey` launch gate and
the five hand-duplicated provider tables). Verdict, element by element:

| MVP element | Verdict | Why |
|---|---|---|

| `type` discriminator (`'openai-compatible'`, designed to admit `'aws'`) | **Adopted** | Lives on `config.providers` entries; the 5 built-ins stay implicit apiKey vendors |

| Live discovery `/api/tags` → `/v1/models` (Unit D) | **Adopted, order inverted** | `/v1/models` is primary (uniform across Ollama/LM Studio/vLLM/generic); `/api/tags` is the Ollama-flavor fallback for older servers |
| http-scheme fix (model-fetcher hardcodes `require('https')` → local discovery silently `[]`) | **Adopted** | New scheme-aware fetch helper shared by the probe and catalog refresh |
| Ollama + LM Studio as built-in registry instances | **Superseded → presets** | Nothing is auto-registered; `--preset ollama|lmstudio|vllm` fills id/baseURL/flavor at add-time. Keeps the static registry closed and the config the single source of user intent |

| Unit F: verify `pricing:null` is tolerated end-to-end | **Superseded** | v4.2 gives local rows an explicit `$0` price (a real tier: priced-at-zero), not tolerated-null. Null-tolerance already exists and stays for direct rows |
| Wizard `baseURL` text field + test-connection (Unit E) | **Adopted** | Electron card + readline branch + a new `amicus provider` CLI |
| Acceptance: `ollama/<model>` launches with no API key | **Adopted** | Now expressible as a hermetic e2e (stub OpenAI-compatible server — the one provider class testable offline) |

## 4. Design

### 4.1 Config schema — `config.providers`

New top-level key in `~/.config/amicus/config.json` (beside `default`, `aliases`, `councils`,
`routing`):

```json
{
  "default": "ollama",
  "aliases": { "ollama": "ollama/llama3.3" },
  "providers": {
    "ollama":   { "type": "openai-compatible", "baseURL": "http://127.0.0.1:11434/v1", "flavor": "ollama" },
    "lmstudio": { "type": "openai-compatible", "baseURL": "http://127.0.0.1:1234/v1",  "flavor": "lmstudio" },
    "vllm-lab": { "type": "openai-compatible", "baseURL": "https://10.0.4.7:8000/v1",  "flavor": "vllm",
                  "name": "Lab vLLM", "apiKeyEnv": "VLLM_LAB_API_KEY",
                  "pricing": { "prompt": 0, "completion": 0 } }
  }
}
```

Per-entry fields:

| Field | Req | Rules |
|---|---|---|
| id (object key) | yes | `^[a-z][a-z0-9_-]{1,31}$`; **reserved:** `openrouter`, `google`, `openai`, `anthropic`, `deepseek` (rejected at add/load) |
| `type` | yes | Enum today: `'openai-compatible'`. Unknown type → entry skipped with a one-line warning (forward-compat for `'aws'`) |
| `baseURL` | yes | Absolute `http:`/`https:` URL only (any other scheme rejected). Windows: no Unix sockets — `http://127.0.0.1:<port>` is the norm. Presets use `127.0.0.1`, not `localhost`, to dodge IPv6-first (`::1`) resolution against servers bound to IPv4 only |
| `flavor` | no | `ollama \| lmstudio \| vllm \| generic` (default `generic`). Drives remediation hints, the `/api/tags` fallback, and preset URLs. Never affects routing |
| `name` | no | Display name (wizard optgroups, `models` grouping). Default: the id |
| `apiKeyEnv` | no | Env-var NAME for an optional bearer. The value lives in the existing `~/.config/amicus/.env` store (0600) — **never in config.json** |
| `pricing` | no | `{prompt, completion}` in $/token, non-negative numbers. Default `{prompt: 0, completion: 0}` — the $0 tier. Override supports metered self-hosting |

New module **`src/utils/local-providers.js`** (the merge layer): `getLocalProviders()`
(validated, normalized map read from config — lazy-required per the route-launch.js pattern, no
require cycle into the static registry), `isLocalProvider(id)`, `deriveKeyEnv(id)`
(`VLLM_LAB` ← `vllm-lab` → `VLLM_LAB_API_KEY`), `validateProviderEntry(entry)`. Invalid entries
are skipped with a stderr warning, never fatal (config.js's forgiving posture). The static
`provider-registry.js` is untouched — the existing 5-vendor registry and all derived maps keep
their exact current shape (migration/back-compat: an absent `providers` key is byte-identical
behavior to today).

### 4.2 Routing integration — a third route class: `local`

`RouteResult.gateway` gains the value **`'local'`** (today `'direct' | 'openrouter'`). The
`--gateway` enum stays `auto|direct|openrouter` — no new flag value.

**`resolveRouteForLaunch` (route-launch.js)** assembles two new injected inputs when the parsed
descriptor's vendor is a configured local provider:

- `localProviders` — the normalized map from `getLocalProviders()`.
- `localLive` — the result of a **bounded live probe** (2s): `GET {baseURL}/models` (i.e.
  `/v1/models` for a standard baseURL) with the bearer attached when configured; on an
  ollama-flavor 404, fallback `GET {origin}/api/tags`. Result:
  `{status: 'ok'|'unreachable'|'skipped', models: ['<id>/<model>', ...]}`.
  Skipped entirely when `validateModel === false` (the probe *is* the remote model-existence
  check — `--no-validate-model` bypasses it, consistent with #61's contract).

**`resolveRoute` (gateway-router.js)** gets one new branch, placed after descriptor
normalization and the explicit-OR handling, *before* the gateway-only-vendor check (so a local
id shadows an OpenRouter vendor namespace of the same name — see collisions below). For a local
vendor:

1. Explicit `openrouter/<localId>/…` literal, or `gatewayMode === 'openrouter'` →
   `routeError('no_openrouter_route')` — local providers never route via OpenRouter.
2. `apiKeyEnv` declared but no value present (env / `.env`) → `routeError('no_local_key')`
   (hint: `amicus key <id> <token>`). Credential pre-flight parity with direct vendors.
   Keyless providers skip this check entirely.
3. `localLive.status === 'unreachable'` → `routeError('local_endpoint_unreachable')` with a
   per-flavor hint ("Is Ollama running? `ollama serve`" / "Start the LM Studio server" /
   generic "check <baseURL>"). Never reached under `--no-validate-model`.
4. `localLive.status === 'ok'` and the model is absent from the live list → `invalid`:
   `selection_required` when `allowSelection` (suggestions = the live list, capped at 6), else
   `routeError('model_not_found')` (ollama-flavor hint: `ollama pull <model>`).
5. Otherwise → `resolved { gateway: 'local', executableId: '<id>/<model>' }`.
   `gatewayMode === 'direct'` **accepts** local routes (a local endpoint is direct-in-spirit:
   no gateway margin, user-held credential); provenance still records `'local'`.

The tri-state contract is preserved: `localLive.status === 'skipped'` behaves as `unknown` —
resolve with an "unverified; attempting anyway" notice, never block. `classifyModel` and the
cached-catalog gate are **bypassed** for local vendors — local rosters churn (pull/rm) far
faster than the 24h cache, so route-time truth is the live probe, not the cache.

**Name collisions/shadowing:** the reserved-id rule protects the 5 built-ins. A local id that
collides with a *gateway-only* OpenRouter vendor (e.g. a local provider named `qwen`) shadows
that namespace for bare descriptors — user config wins, matching the alias precedent —
and `provider add` prints a warning when it detects the shadowing. An explicit
`openrouter/qwen/…` literal still reaches OpenRouter (grammar outranks shadowing).

**Untouched paths (verified):** `maybeMigrationNotice` fires only on `gateway === 'direct'`;
`buildSuggestions`/`gatewayIds`/divergent-vendor machinery never sees local vendors;
`buildLaunchKeys` shape unchanged (the local branch checks `apiKeyEnv` directly); fanout's
per-leg routing (`fanout-validate.js`) and continue/resume provenance inherit the new class for
free since they all flow through `resolveRouteForLaunch`.

### 4.3 Engine wiring — `buildProviderModels`

For every provider id present in `getLocalProviders()`, `buildProviderModels()` (config.js)
additionally emits the OpenCode provider block (the MVP's Unit C, modernized):

```js
providers[id] = {
  npm: '@ai-sdk/openai-compatible',
  name: <display name>,
  options: { baseURL, ...(apiKeyEnv ? { apiKey: `{env:${apiKeyEnv}}` } : {}) },
  models: { '<modelID>': {} }   // from aliases + resolvedRoutes, exactly as today
}
```

`{env:VAR}` interpolation is confirmed in the engine binary — **no key material ever enters the
config object**. `loadCredentials()` (env-loader.js) additionally projects each configured
`apiKeyEnv` from `.env` into `process.env` at bootstrap (same never-overwrite rule), so the
engine's interpolation finds it. The catalog-broadening loop already skips non-direct vendors,
so local aliases get no `openrouter/` mirror (correct). `parseModelString` handles
`ollama/qwen3:14b` fine — colons live inside the modelID; nothing keys off `:free` outside the
`openrouter/` namespace.

### 4.4 Catalog treatment

- **Cached catalog gains local rows at refresh.** `fetchAllModels` includes every configured
  local provider via the new scheme-aware fetch (2s timeout, `[]` on failure): rows
  `{id: '<pid>/<model>', name, contextLength: null, pricing: <provider pricing, default {0,0}>,
  authoritative: true, local: true}`. This feeds `amicus models` (grouped under the provider's
  display name), the pickers, and alias auditing.
- **Refresh-success guard extension (regression trap found during design):**
  `refreshCatalog()`'s "did the network refresh succeed" filter currently excludes only the
  `anthropic/` floor. Local rows must ALSO be excluded from `networkRows` — otherwise an
  offline-except-localhost refresh would count as a success and **clobber a previously good
  OpenRouter cache** with a local-only list. One-line filter change + test.
- **Council resolution drop-guard:** `resolveCouncilMembers()` drops members absent from a
  non-empty catalog. A member whose vendor is a configured local provider is **never dropped on
  catalog absence** (the server may simply have been off at refresh — that is `unknown`, not
  delisted). The leg itself will fail pre-flight with the actionable unreachable error if the
  server is truly down.
- **Local-chair eligibility (D11, Christian, 2026-07-22): a local model MAY chair a council.**
  The council no-drop guard above changes which members survive into `resolveCouncilMembers()`'s
  output (`bench`/`o.models`), and that same list is the exclusion set
  `pickFallbackChair(statsRows, bench, failedChair)` (`src/council/run-chair.js`) draws from when
  picking a fallback synthesizer — its only other exclusion is the hardcoded `'claude'`. The
  primary `--chair` flag (`cli-handlers-council-run.js`) is validated only as "not a bench seat".
  So a local seat can already be promoted to verdict-synthesizer, and this is deliberate, not an
  oversight: **no local-vendor exclusion is added to `pickFallbackChair`, and no `--chair` guard
  is added.** Rationale: an air-gapped council needs a local chair or it cannot run at all —
  excluding local seats from the chair role would strand the fully-offline case this release
  exists to serve. Trade-off accepted per the §2 Non-goals posture (small local models are
  unreliable tool users / less capable synthesizers than a frontier model): the user retains
  control via an explicit `--chair` to pin a stronger seat when one is configured. If experience
  shows local chairs produce materially worse verdicts, a future revision can revisit this —
  until then, absence of a local-chair guard is D11, not a gap.

### 4.5 The $0 pricing tier

- **`lookupPricing` fallback:** no catalog row + vendor is local → return the provider's
  configured `pricing` (default zeros). The budget gate (`checkBudget`) then sees local legs as
  *priced at $0* — per-$/Mtok gate trivially passes, `--max-cost` estimates add 0, and legs are
  NOT counted/surfaced as "unpriced". The "(N unpriced legs — direct provider…)" line keeps its
  current meaning for keyless direct rows.
- **`resolveLegCost` explicit-zero branch:** today `est > 0` is required for
  `source:'estimated'`, so a $0 leg would fall through to `unknown`/null. New rule: when
  pricing is present and the estimate is exactly 0, return
  `{amount: 0, currency: 'USD', source: 'estimated'}`. Spend-ledger rows for local runs then
  carry a real `0` — `amicus spend` totals are unchanged arithmetic, `sourceMix` counts them as
  estimated, `formatCost` renders `~$0.0000`. **No schema bump** (values fit the existing
  shapes end-to-end: ledger v1, spend doc, wave rollups).
- **Key-add picker:** `pricePerMInputFrom` (provider-default-picker.js) gains a fallback to the
  row's OWN `pricing` when there is no OpenRouter twin — local rows display `$0.00/M in`
  instead of "n/a". `runProviderDefaultFlow`'s vendor gate widens from `isDirectProvider(p)` to
  `isDirectProvider(p) || isLocalProvider(p)`; for a local vendor with no cached rows yet, the
  choice list is built from the live probe list. The OpenRouter keyless catalog remains the
  only *fetched* price source (v3.2.0 posture unchanged); local zeros are authored config.

### 4.6 Wizard + key UX

**New CLI `amicus provider`** (new `src/cli-handlers-provider.js`; registered in cli.js's
`USAGE_COMMAND_BLOCKS` so `getCommandNames()`/typo suggestions pick it up):

```bash
amicus provider add ollama --preset ollama            # fills baseURL http://127.0.0.1:11434/v1 + flavor
amicus provider add lmstudio --preset lmstudio        # http://127.0.0.1:1234/v1
amicus provider add mylab --url https://10.0.4.7:8000/v1 --bearer-env MYLAB_API_KEY
amicus provider add mylab --url ... --bearer <token>  # stores under derived MYLAB_API_KEY in .env
amicus provider list | test <id> | remove <id>        # all support --json
```

- `add`: validates id/url (reserved ids, scheme allowlist), warns on gateway-vendor shadowing,
  probes, prints "N models found", then runs the shared default picker
  (`runProviderDefaultFlow`) → writes `aliases.<id> = <id>/<model>` and seeds `config.default`
  when absent (the exact v3.2.0 no-clobber semantics), so `amicus start --model ollama` works
  immediately. A failed probe still saves the entry (warn + flavor hint) — air-gapped
  provisioning must not require the server to be up. `--json` is fully non-interactive.
- `test`: probe + model count + bearer state. `remove`: deletes the entry, offers cleanup of
  the vendor alias / default, and reminds about the `.env` bearer line.
- **`amicus key` awareness:** the list view shows local providers ("no key required" or masked
  bearer hint); `amicus key <localId> <token>` validates via a bearer-attached probe (not
  `VALIDATION_ENDPOINTS`) and stores under `apiKeyEnv`; `amicus key <localId> --remove` works.
- **Readline wizard:** after key detection, one new question — "Add a local / self-hosted
  server (Ollama, LM Studio, vLLM)? (y/N)" → mini add-flow (preset pick or custom URL → probe →
  picker). Configured local providers are listed alongside detected keys.
- **Electron wizard (keys step):** a 6th card "Local server — Ollama · LM Studio · vLLM". URL
  **text** field (not the password field), preset chips, optional bearer (password field),
  "Test connection" → new IPC handler (`ipc-setup.js`) running the same probe; success shows
  the model count. The per-provider default picker step reuses the $0 rows.

### 4.7 Doctor (+ C8)

- **New check `local-providers`:** skipped (`ok`, "none configured") when `config.providers` is
  empty; otherwise probes each provider (2s): `ok` "ollama: 12 models @ http://127.0.0.1:11434/v1",
  else `warn` + flavor hint. **Warn, never error** — a napping local server must not flip
  doctor's exit code in CI (parity with the electron/credit checks).
- **C8 — wizard finale:** both `runReadlineSetup()` and the Electron path of
  `runInteractiveSetup()` end by running `runDoctorChecks()` and printing a **compact** summary:
  only non-ok lines plus "N error(s), M warning(s) — run `amicus doctor` for details" (all-ok →
  a single "doctor: all N checks pass" line). Guarded end-to-end: a doctor bug never fails or
  blocks setup.

### 4.8 `amicus init` (C2)

- **Extraction:** postinstall's registration core (`installSkill`, `installCouncilSkill`,
  `registerClaudeCode`, `registerClaudeDesktop`, `migrateLegacyMcp`, `MCP_CONFIG`,
  `addMcpToConfigFile`) moves to **`src/utils/claude-register.js`**; `scripts/postinstall.js`
  becomes a thin consumer with byte-identical behavior and preserved exports (its test suite
  keeps passing unmodified).
- **Command:** `amicus init [--claude] [--desktop] [--json]`. No flags = both targets. Steps:
  skill installs → MCP registration (CLI-first, file fallback — the existing merge semantics
  that preserve a user's `env` keys) → legacy `sidecar` entry migration → compact doctor
  summary. Idempotent; reports each step as `added`/`updated`/`unchanged`.
- **What init does that postinstall doesn't:** works for **plugin-channel installs**
  (`AMICUS_SKIP_POSTINSTALL=1` skips postinstall entirely — its skip message now points at
  `amicus init`), works after `--ignore-scripts`, repairs deleted `~/.claude` state on demand,
  gives per-step visibility, and offers `--json` for automation. **What init does not do:**
  keys/model setup (`amicus setup`) or engine/electron provisioning (`amicus doctor --fix`).

### 4.10 Security posture

- `baseURL` is user-supplied and requests originate from the user's own machine — SSRF-class
  concerns are self-directed and accepted; documented as such. Still: scheme allowlist
  (`http`/`https` only — no `file:`, no pipes), probes follow **no redirects** and attach the
  bearer only to the configured origin, and the probe/catalog fetch reuses the 2s/5s timeout
  discipline.
- **No key material logged or displayed:** bearer values are masked via the existing
  `readApiKeyHints` pattern; probe logging redacts `Authorization`; config.json never holds
  tokens (`apiKeyEnv` indirection into the 0600 `.env`); `check:secrets` continues to gate
  commits.
- Non-loopback `http://` baseURL + a configured bearer → one-time warning at `provider add`
  (plaintext credentials on the LAN).
- Windows: loopback presets use `127.0.0.1` (IPv6-first `localhost` gotcha), no Unix-socket
  support (documented), no shell involved in probes (plain `http`/`https` core modules).

## 5. Error handling

- New `model_route_error` reasons wired through the existing shared renderer
  (`route-error.js` `REASON_TEXT` + structured MCP/CLI parity for free):
  `no_openrouter_route`, `no_local_key`, `local_endpoint_unreachable` (+ reuse of
  `model_not_found` with flavor-specific hints). Fanout legs inherit per-leg failure documents
  (`buildRoutingFailureLeg`) unchanged.
- `provider add/test/remove` failures: exit 1 + hint; `--json` uses the standard error-doc
  (`failJson`/`ERROR_CODES`). A probe failure during `add` is a **warning**, not a failure
  (entry saved; air-gap rule).
- Engine-side failures that slip past pre-flight (server died between probe and launch, model
  OOM) surface through the existing headless error paths; the unreachable pre-flight makes the
  opaque-SDK-error case rare rather than default.
- Wizard/doctor/init additions are all guarded: no new code path may fail `setup`, `init`, or
  a launch on its own bug (house best-effort pattern).

## 6. Testing strategy

- **Unit — local-providers module:** validation matrix (id regex, reserved ids, scheme
  allowlist, unknown `type` skipped-with-warning, pricing override bounds, `deriveKeyEnv`).
- **Unit — router matrix additions:** {local vendor} × {gatewayMode auto/direct/openrouter} ×
  {bearer: none-declared / declared-missing / declared-present} × {probe ok/unreachable/skipped}
  × {model in/absent from live list} × {explicit `openrouter/` literal} × {shadowed OR vendor}.
  Pure — probe result injected.
- **Unit — engine wiring:** `buildProviderModels` emits `npm`/`options.baseURL`; `{env:VAR}`
  apiKey only when `apiKeyEnv`; no `openrouter/` mirror for local aliases; `loadCredentials`
  projects bearer envs.
- **Unit — probe/fetch:** http AND https, timeout, `/api/tags` fallback on ollama-flavor 404,
  redirect not followed, header redaction.

## Resolved questions (Christian, 2026-07-19)

**Decision: all recommendations below adopted as written**, with the amendment that LM Studio
gets full parity with Ollama throughout (presets, probes, hints, docs) and is the primary
smoke-test target (§ Testing). The Q&A is preserved verbatim for the rationale record.

1. **Command surface: new `amicus provider` command group?**
   Recommendation: **yes** (`provider add|list|test|remove`). It is discoverable, scriptable
   (`--json` for air-gapped provisioning), keeps `amicus key` meaning "secrets", and gives
   `type:'aws'` a home later. Alternative (folding into `setup`/`key` flags) saves a command
   name but buries the headline feature of the release.

2. **`--gateway direct` on a local vendor — accept or reject?**
   Recommendation: **accept** (resolve to the local route; provenance says `local`). "Direct"
   to a user means "not through OpenRouter's meter", which a local endpoint satisfies; erroring
   would force scripts to special-case local seats in mixed fanouts. The strict alternative (a
   new `--gateway local` enum value) adds surface for no real disambiguation win.

3. **Unreachable endpoint at launch: hard pre-flight error, or warn-and-attempt?**
   Recommendation: **hard error with the flavor hint** ("Is Ollama running? `ollama serve`"),
   `--no-validate-model` as the escape hatch. The engine's failure for a dead endpoint is an
   opaque SDK error after spawn; a 2s pre-flight with remediation is the whole UX win. Risk
   accepted: a cold-starting server needs a retry or the escape hatch.

4. **$0 default with an optional per-provider `pricing` override — ship the override now?**
   Recommendation: **yes.** It is ~10 lines on top of the fallback path, it makes the generic
   type honest for metered OpenAI-compatible endpoints (Groq/Together used off-label), and it
   serves chargeback-style self-hosting. Strictly-$0 is simpler but bakes in a lie for those
   users.

5. **Local rows in the shared cached catalog — include (with the refresh guard) or live-only?**
   Recommendation: **include.** `amicus models`, the pickers, and alias audit all read the
   cache; live-only would make local models invisible whenever the server naps. Routing never
   trusts the cache for local vendors anyway (live probe), so staleness costs nothing at
   launch time.

6. **Shadowing gateway-only vendors (a local provider named `qwen` hides OpenRouter's `qwen`
   namespace for bare ids) — allow with a warning, or reject curated-vendor collisions too?**
   Recommendation: **allow + warn at `provider add`** (user config wins, the alias precedent;
   explicit `openrouter/qwen/…` literals still work). Rejecting would need a maintained
   blocklist of OR vendor names that goes stale.

7. **`amicus init` default scope: both Claude Code + Desktop, with `--claude`/`--desktop` to
   narrow?**
   Recommendation: **both by default** — it mirrors what postinstall does today, so "init =
   postinstall on demand" stays a one-sentence mental model; the flags cover surgical re-runs.
   (C2's literal `init --claude` still works and means "Claude Code targets only".)

8. **Wizard-end doctor (C8): compact non-ok summary, or the full check table?**
   Recommendation: **compact** (non-ok lines + counts + "run `amicus doctor` for details"; a
   single all-good line otherwise). The wizard just printed its own summary; 14 more lines of
   green checks buries the "Setup complete!" moment.
