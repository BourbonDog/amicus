## 3. The rule the whole design rests on

Six candidate designs were adversarially refuted. Eleven "fatal" findings; **ten were the same defect**:

> A design moves identity `X` into a new space at site A, leaves it in the old space at site B, and never enumerates that A and B join.

Verified instances: `adjudications[].judge` vs `revoteByJudge` (`debate.js:60-64` ← `run-debate.js:126,:151`); `meta.models` vs `adj.judge` (`report.js:37-40`, `matrix-model.js:47,:53`); `data.seat` vs `deadBenchSeats` (`verdict.js:38-39,:72,:87`); `meta.taskMode` undeclared on the MCP tally shape (`mcp-tools.js:393-397`) vs `tally.js` reading it; `run.js:271` gated vs `cli-handlers-council.js:39` and `mcp-server.js:1427` ungated.

**RULE OF ONE SPACE.** Within a single artifact, an identity has exactly one space. When the space changes, the **roster, the keys, and the values change together** — never one of the three. Where two spaces genuinely must coexist (seat ↔ model), they coexist as **two fields on one carried object**, never as two strings joined by a lookup.

Every structural choice below is downstream of this rule.

## 4. Workstream A — Seat identity

### 4.1 What is broken today

Reachable now, with no duplicate bench at all:

- `ledger.js:70` — `meta.models.map(...)` emits **two byte-identical rows** for `--models gpt-5,openai/gpt-5`, both joined to whichever runStats row the model-keyed `Map` at `:68` kept last, each counting the same findings. A single-run double-count, written permanently into an append-only file.

Reachable with a duplicate bench:

- `tally.js:96` — `votes.filter(v => v.judge !== f.raiser)` excludes by **model name**. Two seats on one alias strip every seat's vote from every one of that alias's findings → `basis {a:0,d:0}` → **Singleton for every finding**, on a healthy run.
- `run-launch.js:198` — `review-${sanitizeName(modelInput)}.md`; the second seat **silently clobbers** the first.
- `run.js:203` — `new Map(s2.judgeResults.map(j => [j.judge, j]))` silently drops one twin judge.

`BACKLOG.md:1872-1882`'s claim that *"duplicates mostly work today — the corruption only fires when a duplicated seat dies"* is **STALE**. Its diagnosis (`lensIndexOf` at `run-retry.js:28`, `roleFor` at `run-stages.js:36`) is correct but names 2 of ~11 collapse points.

### 4.2 Seat id

```
seatId := alias                    when that alias occupies exactly one bench seat
        | alias + '#' + N          when it occupies more than one (N = 1-based, bench order)
```

Per **R9**. Consequence, and the entire reason for the shape: **for every bench that has ever run, `seatId === alias` byte-for-byte.** `run.json`, `tally.json`, `verdict.json`, `report.html`, review filenames and ledger rows are unchanged.

`#` is deliberate: `sanitizeName` (`run-launch.js:180`, `/[^a-zA-Z0-9._-]/g → '-'`) maps it to `-`, so `deepseek#2` → `review-deepseek-2.md`. That is a real collision surface against a literal alias `deepseek-2`, and it is why `preflightSeats` rejects post-sanitize filename collisions **loudly, pre-spend**.

Self-describing over opaque: a renderer that forgets a projection prints `deepseek#2` — honest and readable — not `s2`, which is a lie by opacity.

### 4.3 Seats are derived, never minted

`buildSeats(bench, critic, lenses)` is a pure function of data `run.json` **already persists** (`run-state.js` seeds all three). It is therefore **total over every legacy run dir**: a pre-v4.8 run opened in the v4.8 Workspace reconstructs full seat identity even though nothing on disk mentions it. Old runs are *upgradable*, not merely tolerated.

Minted at **`asm.preflightSeats(o)`**, called from `run.js` beside `preflightClaudeReview` (`run.js:124`) — before any launch, zero spend. Not in a handler: `runCouncil` is the shared entry for all four callers (CLI, MCP child, GitHub Action, direct `require`), so all four get an identical table with no handler-signature churn.

Sets `o.seats = [{ id, alias, role, lens, position }]` and `o.criticSeat` (a **seat id**). Rejects pre-spend with `BAD_ARGS`: post-`sanitizeName` seat-id collisions, and an ambiguous `--critic <alias>` when that alias occupies more than one seat (`--critic 'deepseek#2'` is the disambiguated spelling, printed in the hint).

> Budget `preflightSeats` at ~37 lines: `preflightClaudeReview` (`run-assemble.js:74-110`) is 37 lines **with** its docblock.

**Positional index is a derivation input only, never wire identity.** Positional identity was refuted: it blanks the report matrix, inerts blind mode, and deletes the `claude` seat (`run-assemble.js:92-103` rejects `claude` from `--models` while `:170` pushes `CLAUDE_SEAT` onto `meta.models`). Under an alias-derived id that objection dissolves — `claude` is simply a seat whose id equals its alias.

### 4.4 The seat rides on the leg

The mechanism no proposal had, and the one that dissolves four separate fatal findings.

**`bindSeats(waveId, seats, legs) → { bound: [{seat, leg}], unbound: [...] }`** — a pure function in a new `src/council/seats.js`, called at every site that already loops over `wave.legs`. Resolution order:

1. **`leg.legId || leg.taskId`** — `deriveLegIds` stamps `${waveId}-${i+1}` (`fanout.js:30-32`); `runSingleAttempt` sets `doc.legId` (`fanout-leg.js:195`); `buildRoutingFailureLeg` sets only `taskId: legId` (`fanout-leg.js:61`) — hence the `||`.
2. **alias match**, and only when that alias occupies exactly one seat in this launch. For every bench that has ever run, this is today's exact behaviour.
3. **unbound** → a `degrade.note`, **never a guess**. Silent mis-attribution is the failure this feature exists to kill (`artifact-guard.js:72-79`, the RN-1 class).

**Do not index `wave.legs[i]` positionally** — `run-retry.js:261-269` documents partial wave returns in its own comment.

What the stamped seat fixes in one move:

| Defect | Mechanism |
|---|---|
| `run-debate.js:126,:151` — `byJudge[judge]` overwrites the twin | `bindSeats` on the `-rv` wave → `byJudge[seat.id]`; `applyDebate`'s `a.judge === judge` (`debate.js:60-62`) now matches seat-space |
| `run-debate.js:134` — `${waveId}-${judge}r` collides for twins | `${waveId}-${sanitizeName(seat.id)}r` |
| `run-retry.js` **nine** alias↔leg joins (`:43,:98,:217,:226,:229-230,:256,:270-272,:281`) | all key on `seat.id` off the bound leg |

It must emit a wave-derived, per-leg-unique id. No test outside `tests/abort-*.test.js` (which builds its own fixtures) asserts on `mkLeg`'s `taskId`. **This belongs in PR0**, not mid-stream: it is a shared helper across ~30 suites.

### 4.6 Identity is seat-exact; corroboration is labelled (R8)

`assignTier` returns `Confirmed` for `(a===1, d===0)` — verified at `tally.js:22`. Under seat-exact peer filtering, `gemini#2` adjudicating `gemini#1`'s finding is a peer agree, and a model corroborating **itself** would be presented as independent corroboration.

Per **R8**, the signal is kept and labelled rather than discarded:

- The peer filter becomes **seat-exact** — `v.judge !== f.raiser` compares seat ids. This alone stops the `{a:0,d:0}` Singleton collapse, which is the real #137 defect.
- Additionally, a finding whose agreeing peers include any seat sharing the raiser's model carries **`sameModelCorroboration: true`**.
- The chair packet is **required to surface it**, and the report renderers show it.

Rationale for the middle path over model-exact exclusion: on a lens bench, two personas of one model *are* different generations with different framings, and excluding them would make a two-seat lens bench produce strictly **less** peer signal than a one-seat bench — defeating #137's own purpose. Labelling preserves the signal without letting it masquerade as independence.

**Consequences that follow and must not be missed:**

- `tally()` must resolve seat → model, so **`meta.seats` is REQUIRED on the tally input, not optional** — see §7.4.
- Absent `meta.seats` ⇒ `modelOf` is the identity function ⇒ `tally.js:96` reduces to the literal line shipping today. Legacy parity is automatic.
- `sameModelCorroboration` is computed **downstream in `tally.js`**, never emitted by a seat. **`src/council/findings.js` still changes by zero lines.**
- `council-tally.schema.json` gains the field as optional; `briefings-chair.js` (post-PR0) carries the chair-packet wording.

### 4.7 Reliability stays a property of the model

**A seat id must never appear in a ledger row.** The mechanical reason is one line: `pickFallbackChair` **launches** `top.aliases[0]` (`run-chair.js:63`), and `deepseek#2` is not a routable name. A seat is a per-run role assignment with no cross-run referent — `s1` is `gemini` in run A and `gpt` in run B.

The naive "group by model" fix has a permanent bug: for `--models gpt-5,openai/gpt-5` the group has two aliases and `row.model` holds one; the other is never written, `deriveReliability` builds `aliases[]` purely from observed `row.model` (`ledger.js:133-135`), and `pickFallbackChair` then promotes a different name — permanently, in an append-only file.

**So: group by the `(model, resolvedModel)` pair, one row per distinct pair.** `buildLedgerRows` (`ledger.js:62-89`) changes; nothing else in the file does:

- join runStats by `r.seat || r.model` (a legacy row has no `seat` → today's behaviour),
- group the run's seats by `(alias, resolvedModel || alias)`,
- one row per group: `findingsRaised` / `bySeverity` unioned, `confirmRate` / `factErrorRate` over that union, `streetCred*` the mean of the group's seats, `conformance` worst-wins, `role` worst-wins with `critic` ranking above `seat`,
- `sc = new Map(streetCred.map(s => [s.model, s]))` (`ledger.js:64`) becomes **seat-keyed**, then averaged into the group.

`deriveReliability`, `pickFallbackChair`, `LEDGER_JOIN_ROLES`, `appendRun`, `readRows`: **zero edits.** `LEDGER_SCHEMA_VERSION` stays **2** — no new row *field* ships, so there is nothing to version.

### 4.8 The cost bijection

`tests/council/run-cost-bijection.test.js:186-191` is a pre-written acknowledgement of this gap and it fires.

The repair is **not** a key rename to `${waveId}::${seat}` — that is provably unsatisfiable against the test's own ground truth, which reads `leg.waveId` + `leg.modelInput || leg.model` off the leg document (alias space). Seat-space row keys fail multiset equality; alias-space row keys fail uniqueness.

**Key the bijection on `legId`.** The row carries it; the ground truth reads `leg.legId || leg.taskId`. Both sides read the *same field* off the *same leg*, so duplicate seats cannot collide by construction, and `${waveId}-${i+1}` is already the leg's actual primary key — strictly stronger than the `(waveId, model)` proxy. Requires the `fake-launchers.js` fix (§4.4), and the "this suite does not attempt to model it" comment is replaced by a duplicate-bench scenario that **runs through debate** — because that is where both twin-judge defects live, and neither the seat wave nor the judge wave alone would catch them.

- `--critic <alias>` on a bench where that alias occupies two seats now **exits 1 pre-spend** instead of silently stripping both occurrences (`run-stage1-launch.js:47`). Deliberate. CHANGELOG-worthy.
- Ledger row **count** changes for `--models gpt-5,openai/gpt-5`: two rows → one. Wrong to right, but any golden fixture pinning row counts for an alias-divergent bench re-baselines.
- `artifact-guard.js:81-86`'s stated intent inverts.
- New duplicate-bench cases (not repairs) needed in: tally, ledger, debate, run-debate, run-stages, run-stage2, run-retry, run-launch, council-legs, live-normalize, verdict, artifact-guard, cost-bijection — plus a regression pin that `pickFallbackChair` still receives alias-space `o.models`.

## 5. Workstream B — Task mode

### 5.1 What is broken today

`briefings.js:112-115` hard-codes *"You are one reviewer on an independent multi-model review bench…"* onto every Stage-1 brief. There is no intent parameter anywhere. That single hard-coded frame is the shared root of both #130 (seats silently disagree about what the task is) and #134 (the council can only critique, never produce).

### 5.2 The tally is already subtype-blind — verified

This is the finding that makes workstream B **M–L rather than XL**:

- `assignTier` (`tally.js:19-27`) takes two integers.
- `computeStreetCred` (`:49-67`) reads only `rankings`, never touches findings.
- `tally()` (`:91-107`) copies `severity` through as an opaque passenger and branches on it nowhere.
- `nothingToDebate` / `debateTargets` (`debate.js:126-159`) filter on tier alone.
- `severity` is `["string","null"]` and **not required** in `council-tally.schema.json:41-45`, and is `z.string()` with no enum at `mcp-tools.js:399`.

**Therefore the generalization needs no tally work at all**, and two expensive inventions are cut:

**CUT 1 — no vocabulary rename.** Keep `blocker|major|minor|nit` in both modes. This severs, in one stroke: the silent all-zero `bySeverity` (`ledger.js:55-59`, `if (c[f.severity] !== undefined)`), a two-vocabulary append-only ledger, the `ledger.js` edit entirely, and every schema edit. In task mode the **gloss** changes — `blocker` = *the answer fails without this claim*, descending — the enum does not.

**CUT 2 — no `location` → `support` swap, and no new atom.** `support` dies at the validator: `anonymize.js:51-54` emits exactly `{id, raiser, severity, claim, location}`, so it would never reach `tally-input.json`, the judges, or the debate briefing. And `location` is ~0% consumed as data and ~100% valuable as **validator-enforced grounding discipline** — in the mode most prone to fabrication. So: same key, same required-non-empty rule, **mode-scoped gloss only**. In task mode `location` means *what this rests on: a source, a computation, or the literal word `assumption`*.

**Consequence: `src/council/findings.js` — the repo's highest-risk file — changes by ZERO lines.** All 526 lines of `findings.test.js` stay green unedited, and that is the proof of review-mode parity.

**KEEP:** `findings: []` with a real `overall` is **valid in both modes**. Rejecting the empty set in task mode would re-arm LC-10's fabrication pressure and the F2 repair deadlock, on zero paid-run evidence — and `run-stages.js:142-151` carries an explicit ⚠️ forbidding exactly that. It also keeps `briefings.js:175-181`'s empty-prior branch (which instructs the model verbatim to emit an empty array) from becoming a validator/briefing contradiction.

### 5.3 Schema

**Stage-1 seat artifact: identical in both modes.**

```json
{ "overall": "<non-empty>",
  "findings": [{ "id": 1, "severity": "blocker|major|minor|nit",
                 "claim": "…", "location": "…", "rationale": "…" }] }
```

In task mode `overall` **is the seat's deliverable** and `findings[]` are the load-bearing claims it rests on. The shape does not change; the frame and the gloss do.

**New fields:**

| Field | Where | Rule |
|---|---|---|
| `intent: 'review' \| 'task'` | `meta` on `tally-input.json` / `tally.json`; `run.json` | emit-only-when-`task` (the `tag`/`pack` idiom, `run-state.js:110-118`) |
| `intent` | **`verdict.json`** | **mandatory.** `buildVerdict` (`verdict.js:103-139`) copies six meta fields and no meta object, so without it a task `verdict.json` carries nothing any renderer could fork on — and `report.js` / `report-html.js` / `matrix-model.js` / `fold-format.js` all build from the verdict |
| `sameModelCorroboration` | finding, in `tally.json` | R8; computed in `tally.js`, optional in schema |
| `seat` | runStats row | emit-when-set |

`overallVerdict` widens to six values in `council-verdict.schema.json`. Verified safe: no runtime consumer compares it to a literal — the constants live only at `briefings-stage2.js:20` and `parse-stage2.js:16`, and `fold-format.js:66` is already phrase-agnostic.

`schemaVersion` stays **2** on both (the `seatLoss` / `degrades` / `resolvedModel` precedent). No schema needs a constraint loosened: the only `additionalProperties: false` in either council schema is scoped to the `debate` sub-object (`:62`, `:157`).

## 6. Composition: how A and B interact

**One intent per run. `intent` is a run property on `meta`, never on the seat.**

Mechanical, not a scoping preference: Stage 2 is one bundle over all reviews with one ranking axis (`run-stage2.js:52`, `buildJudgeBundle`). A judge ranking a defect review against a research answer is ranking incomparables, and `rankingToOrder` → `computeStreetCred` produces **one street-cred number per seat** that would blend two axes — and under R11 review rows still reach the append-only ledger, so a mixed run would write a `streetCredPeersOnly` derived partly from a ranking against a different kind of artifact, permanently, into the closed loop.

Concretely: `o.intent` is validated in `preflightSeats`'s neighbourhood, lands on `meta`, and `o.seats[]` carries **no intent field**. Putting intent on the seat is a schema commitment that is expensive to reverse and should not be made before a mixed bench is actually wanted.

**Workstream A lands first.** Three mechanical reasons:

1. **Correctness coupling.** Task mode's peer logic *is* `tally.js:96` and `:58`. Building it against alias identity ships the #137 bug in new code — and the task path's primary configuration (#137's own use case: one model, several lens personas) is exactly where R8's stamp has to be right.
2. **Line-gate collision.** Both workstreams edit `run-stage1-launch.js`, `run-stages.js` (291), `run-retry.js` (295), `run.js` (295), `run-assemble.js` (257). Concurrent waves on files with ≤9 lines of headroom is how CI breaks — and A's extractions are what *create* the headroom B needs.
3. **Live bug before new capability.** A closes corruption reachable today; B is net-new.

There is no reverse dependency: B needs `o.intent` on `meta` and a forked chair parser, neither of which touches seat identity.

## 7. Migration and backward compatibility

Governing rule: **v4.7 GOA-7's legacy-read precedent** (`ledger.js:7-13`) — readers never inspect `schemaVersion`; an absent field implies legacy; rows are never migrated.

### 7.1 Old run dirs
`run.json` gains `seats[]`, `criticSeat`, `intent` — all additive. Because seats are **derived** (§4.3), a pre-v4.8 `run.json` is upgradable in memory, so `council-legs`, `artifact-guard`, `run-detail` and the Workspace **reconstruct rather than degrade**. `roleFor` keeps its `o.models.indexOf` fallback when `o.seats` is absent, so `amicus status`, `amicus watch` and `cli-handlers-pack.js:69`'s round-trip of `run.bench` read an old run identically.

### 7.2 Old `tally.json` / `verdict.json`
runStats rows have no `seat`; every new consumer reads `r.seat || r.model`. `meta.seats` absent ⇒ `modelOf` is identity ⇒ `tally.js:96` reduces to the literal line shipping today ⇒ a v4.7 tally-input tallies to a byte-identical record. `intent` absent ⇒ `review`.

### 7.3 Old ledger rows
Never rewritten, never re-keyed, never migrated. `LEDGER_SCHEMA_VERSION` stays 2. `aliases[]` still contains only alias-space names because the seat→alias projection runs **before** the row is written, so `pickFallbackChair` keeps promoting a routable alias in both eras. One honest wrinkle: for the alias-divergent bench, historical rows double-counted and new rows do not — those numbers change from wrong to right.

### 7.4 MCP surface

1. **`amicus_council_run`** gains `intent: z.enum(['review','task']).optional()`. **`.optional()`, never `.default()`** — a `.default()` materializes the key pre-handler and makes *"caller said review"* indistinguishable from *"caller said nothing"*. Default applied at the read site in `mcp-council-run.js`. Same rule for the seat-aware `--critic`.
2. **`amicus_council_tally`'s `meta` shape MUST declare `seats`.** `mcp-tools.js:393-397` declares six named keys; zod is `^3.0.0` (`package.json:85`), whose `z.object` **strips** unknown keys; `mcp-server.js:1539` registers that raw shape as the tool's `inputSchema` and `:1421-1423` hands parsed input straight to `tally(input)`. Without the declaration `meta.seats` never arrives, `modelOf` silently degrades to identity, and a hand-assembled duplicate-seat tally computes the wrong basis **with no error**. Add `seats: z.array(z.object({ id: z.string(), model: z.string() })).optional()` and `intent: z.string().optional()` on the same object.

`COUNCIL_PACK_PARAM_MAP` (`mcp-council-run.js:40-44`) maps MCP keys onto `pack-resolve.js`, which is at **300/300**. `intent` is therefore **not pack-settable in v4.8** — a stated limitation, not an oversight.

### 7.5 Forward safety
A v4.8 run with a unique bench and `intent` absent produces byte-for-byte identical `run.json` (modulo additive `seats[]`), `tally.json`, `verdict.json`, `report.html`, review filenames and ledger rows. The only value an old reader cannot interpret is `meta.models` containing `alias#N` — and old readers only display it, where `deepseek#2` reads correctly to a human. That is the entire payoff of R9's self-describing id.

**Cold start — RULED (R14).** ⚠️ **First, a correction that changes what this workstream is.** The
backstop is **disarmed permanently by the first `progressed` tick** (`no-output-backstop.js:9-11,:40`),
and `progressed` is very broad — `outputGrew || toolActivity || resultActivity || messageActivity ||
newAssistant || reasoningActivity || settleActivity` (`headless.js:858-859`). Its own docblock says
*"a 30-90s cold-prefill local model is never affected."* **The backstop does not kill slow models. It
kills silent ones.** #129's title ("kills slow-but-alive models") describes something the code does
not do. What bench adaptation must learn is therefore narrower and cleaner: **time-to-first-token**,
not duration. The CHANGELOG must describe the real change, or we ship a fix whose release note claims
a bug that isn't there.

The rule, and why it inverts the usual instinct:

- **Too short** kills a healthy seat that was merely slow to first token — costs a seat, the money
  already spent on that leg, a wrong diagnosis, and the half-hour #129 documents.
- **Too long** lets a genuinely silent model burn the extra window — costs wall-clock **only**, since
  by the definition of the class it has produced zero tokens.

So with no evidence, longer is the safe direction:

- `DEFAULT_NO_OUTPUT_BACKSTOP_MS` **120 000 → 300 000** as the no-history value.
- With ≥3 observations — **reuse `lowN` (`ledger.js:137`), do not invent a second threshold** —
  derive `max(FLOOR, k × p95 TTFT)`. For proven-fast models that lands *below* 300 s, which is where
  the adaptation pays for itself and wins the wall-clock back.
- Keep the env knob and the documented `ms <= 0` escape hatch byte-for-byte. **No new config knob** —
  `BACKLOG.md:1893-1895` already ruled a knob is neither self-heal nor self-diagnose, and it could not
  be stored anyway: `saveConfig` (`config.js:63`, verified) strips any alias whose value is not a
  string.
- **Free seed:** `models --check --live` already runs one real leg per stored alias with real spend
  rows (`models-probe.js:63-82`). Record TTFT while it is there. This creates no cold-start obligation
  (opt-in, costs money), but anyone who has run it once starts seeded. Its window is
  `PROBE_WINDOW_MS = 30000`, so it can observe TTFT ≤30 s only — which is exactly right: **the probe
  seeds the downward adjustments, real runs seed the upward ones.** The 300 s default widens that gap,
  which makes the seed more valuable, not less.

## 10. What this design does NOT solve

1. **The duplicate-seat path is exercised only by tests, never by a typical run.** Accepted with eyes open — artifact parity (R9) is what keeps the migration a paragraph and the ledger un-re-keyed. Mitigation (duplicate-bench cases in fourteen suites + one CI end-to-end council **that runs through debate**) converts "never exercised in production" into "always exercised in CI." **That is not the same thing.** A future edit reverting one join to `modelInput` passes everything and misbehaves only for the user who asked for duplicates.
2. **Task mode has zero paid-run evidence.** The gloss, the `ANSWER:` scale and the concurrence framing were designed from first principles in one pass. The review contract earned its shape from five paid councils' worth of documented failures (LC-6, LC-10, LC-11, LC-12, F2). Expect the **gloss**, not the seam, to be what changes — and under R10 that revision is a breaking-change story, not a free one.
3. **Tiers in task mode measure concurrence, not truth.** `assignTier` counts peers; models correlate on priors. The qualifier and the R8 stamp make the artifact honest; they do not make the number more informative.
4. **No generative reliability history** (R11). `amicus council stats` under-reports with no in-band way to say so. Docs-only mitigation; permanent known gap until the v4.9 `intent`-axis lift.
5. **No mixed-mode bench** (§6). One council cannot both critique an artifact and produce an answer.
6. **`amicus council verdict <tally.json>` / `council tally` on a task run** have no valid input path and must fail with a named `COUNCIL_INTENT_MISMATCH`, not an ENOENT. `council validate` stays mode-free by design.
7. **The `<waveId>-<i+1>` legId convention is an unpinned cross-module contract.** `bindSeats` prefers it and falls back to alias-match, so a fanout renumbering degrades to today's behaviour rather than mis-attributing — but a pin test in `tests/sidecar/` is required.
8. **`overall` cannot be validated for substance.** In task mode it *is* the deliverable, and nothing stops a one-line answer with three well-formed claims. The chair's synthesis is the real deliverable and is not validated either.

### 11.4 The anti-rot changes (R19)

This kickoff surfaced ~15 instances of one failure: **a document asserts a fact about code, and
nothing fails when the fact becomes false.** Every stale row in §9 is that shape.

The sharpest case is `remediation-hints.js:117`, because a test makes it *worse*:
`tests/remediation-hints.test.js:93` pins the literal `"4.7.1"`. When v4.8 ships the test still
passes — **it pins the claim rather than the invariant, so it actively defends the rot.** A test can
be part of the loop.

Three changes, in leverage order:

1. **Stop writing rot-prone numbers into prose.** Line counts, file counts, suite counts and version
   literals in `BACKLOG.md`/`docs/ROADMAP.md` have no reader who needs them and no mechanism keeping
   them true. Delete them; point at the command that computes them. **Canonical instance:**
   `ROADMAP.md:248`'s tight-file list has rotted three revs running — it currently names
   `cli-handlers-council-run.js` and `run-debate.js` (both 283, out of band) while the three files
   actually at 300 go unnamed. Correcting it a fourth time buys one release of accuracy; replacing it
   with a pointer to `npm run check:sizes` buys permanent accuracy.
2. **Where a doc must assert a code fact, make the assertion executable.** The repo already does this
   well — `docs-council-toc-anchors` parameterizes over real TOC links; the design-token drift guard.
   **First target, already in scope:** the `skills/` gate extension, aimed at the tier vocabulary —
   one test that reads the tiers from `tally.js` and asserts every doc naming them agrees. That fixes
   `skills/second-opinion/SKILL.md:299` and `COUNCIL-DESIGN.md:155` and prevents recurrence.
3. **Split `BACKLOG.md`'s two jobs.** Items appear twice in opposite states (`:1676-1753` vs
   `:1825-1832`; `:1547` vs `:1773-1774`) because one document is both a work queue and a historical
   record with no rule for which wins. The queue holds open items only; shipped work leaves entirely.

**On just-in-time planning.** Keep it — but it is one of three practices, not the fix. JIT addresses
plans written far ahead of execution. **The rot found at this kickoff was not in plans; it was in the
persistent documents plans are written *from*.** `BACKLOG.md` is the input to every plan, so JIT alone
converts "stale plan from a stale backlog" into "*fresh* plan from a stale backlog" — arguably a worse
trap, because a freshly-dated plan carries more authority. A plan written straight from `BACKLOG.md`
at this kickoff would have re-implemented GOA-7 (shipped in v4.7) and under-scoped #137 by ~9 sites.

What actually caught it, and what must therefore be written down as practice rather than left
incidental:

- **verify-against-source as an instructed step** — the scope map's readers were told explicitly: *"if
  a document's claim contradicts the source code, say so and mark the doc STALE."*
- **adversarial refutation before a design becomes a plan** — 10 of the design panel's 11 fatal
  findings were the single defect class in §3.

Scope note: the loop is confined to the prose layer. Twelve consecutive first-attempt publishes say
the shipping machinery is sound. The risk is not a project in trouble; it is that plans keep being
written from the half that stopped being trustworthy.
