# Amicus v4.3 — "See runs live in the terminal — and never waste one" (Design)

**Status:** finalized (Christian, 2026-07-19) — all recommendations adopted as written
**Baseline:** v3.2.3, main `aa2440b` (+ the v4.0 engine design, which v4.3 assumes shipped:
`2026-07-19-v4.0-headless-council-engine-design.md`).
**Inputs:** `docs/ROADMAP.md` v4.3 entry (locked scope); enhancement-council proposals
F3/D6 (observability), F2/E10/E8 (resilience), A4-basic/E3/E4/E9/D7/C9 (spend);
BACKLOG.md:280/:285 (continue/resume zero-spend + waveId-in-rows, both pre-inventoried).
**Release:** ships as **v4.3.0** (additive within the 4.x line; no breaking doc shapes).

## 1. Goal

Three benefits users feel, one data layer underneath:

1. **See runs live:** `amicus watch <waveId|councilRunId|taskId>` renders any in-flight run —
   stage, messages, tokens, cost-so-far, per leg — from any terminal, any process. `--follow`
   streams milestone events from a launching fanout/council process; `--on-complete` fires a
   user command (CLI) or an MCP notification (MCP) at terminal state.
2. **Never waste a run:** `fanout --retry-failed <waveId>` relaunches only the dead legs;
   opt-in cheaper-model fallback chains substitute a seat on rate-limit/overload instead of
   failing the leg; spend consumed by failed legs becomes visible instead of silent.
3. **See where every dollar went:** continue/resume finally write ledger rows; every row is
   attributed (wave, council run, project, gateway, outcome); `amicus spend` grows filters and
   group-bys that answer "what did this council cost?" directly.

The **data-layer interface contract** (§4) is the headline deliverable: it is the exact surface
the v4.4 Electron "Council Workspace" consumes. v4.4 adds pixels, not plumbing.

## 2. Non-goals

- **`--dry-run` / cost & route preview** — explicitly backlogged by the roadmap (E2/C7/F4).
  Nothing in this design depends on it; nothing here implements any part of it.
- **Webhooks / SSE / any listening server** (the other half of D6) — no HTTP surface, no
  standing event server. `--on-complete` is exec + mcp-notify only.
- **The Electron GUI** (B9) — v4.4. This spec only guarantees the data it will read.
- **Spend governance** (the enforcement half of A4: per-team caps, budget alerts, org
  ceilings) — v5.0. v4.3 is visibility and attribution only; the existing pre-flight budget
  gate (`src/sidecar/budget.js`) is unchanged.
- **Config-sourced hooks / plugin system** (D8, withdrawn) — hook commands come from the
  command line of the current invocation only, never from config files or run artifacts.
- **New MCP streaming/watch tool** — `amicus_wait` remains the MCP blocking primitive; the
  MCP surface changes are limited to an `onComplete` input and (open question 1) one
  read-only `amicus_spend` tool.
- **Automatic same-model retry / backoff loops** — retry is manual (`--retry-failed`);
  fallback is substitution, not repetition (see §6.2 and open question 3).
- **Solo-run events and hooks** — `--follow`/`--on-complete`/events.jsonl apply to fanout
  waves and council runs in v4.3; solo `start` runs are watchable via snapshots only.

## 3. Locked design decisions (proposed)

1. **The contract is files + polling. No push, no IPC, no fs.watch.** Every consumer (watch,
   GUI, scripts) reads the same on-disk state the orchestrator writes; liveness comes from
   polling. Windows is the reference platform and `fs.watch` is not trustworthy there
   (ReadDirectoryChangesW event loss under load; rename-swap atomic writes surfacing as
   confusing delete+create pairs; OneDrive/AV filter drivers delaying or swallowing events).
   Poll-based tailing at 0.5–2 s is deterministic, cheap, and already the house pattern
   (mcp-wait polls at 2 s; wave heartbeat samples at 15 s).
2. **Three data surfaces** (§4): durable **snapshot files** (existing, formalized),
   a new append-only **event stream** (`events.jsonl` per wave/council run), and the
   **composed live doc** (the `amicus_status` rollup, stamped `view:'live'`).
3. **watch UX: in-place refresh table on a TTY, milestone lines otherwise** (§5.1) —
   auto-detected, with `--plain` and `--json` overrides. No TUI dependency; ANSI only.
4. **retry-failed creates a NEW linked wave**, never mutates the original (§6.1).
   `wave.json` stays immutable once written; links live in metadata and the new wave's doc.
5. **Fallback chains are opt-in** (`--fallback` / config), fire only on classified
   rate-limit/overload errors, walk per leg, and re-route every substitute through the #61
   gateway router. Substitutions are first-class recorded events, never silent (§6.2).
6. **Failed-leg spend is an attribution fix, not a collection fix** — partial usage on
   error/timeout legs is *already* captured and appended (runHeadless returns `usage` on its
   error paths; fanout-leg appends unconditionally); rows just can't be told apart today.
   Rows gain `status`/`op`/attribution fields; rollups grow a `wasted` view (§6.3, §7).
7. **Spend query = flags on the existing `amicus spend`**, not a new subcommand; MCP gets at
   most ONE read-only `amicus_spend` tool (open question 1). Tool count 15 → 16 worst case.
8. **Envelope discipline:** all new emitted docs carry `{schemaVersion, type}` (result
   family, current version); all changes to existing docs are additive. The two JSONL
   ledgers stay internal v1 non-envelope files, per the v4.0 documented exclusion.

## 4. The data-layer interface contract (what v4.4 builds on)

**Principle: process-agnostic.** A run launched by the CLI, the MCP shared server, or CI is
observable by any other process through files alone. All writes are either atomic
(`writeFileAtomic` tmp+rename — the Phase-15 invariant) or single-writer appends; all reads
tolerate absence, torn tails, and transient Windows open failures (EBUSY/EPERM → treat as a
missed tick, retry next poll — the mcp-wait torn-read posture, reused verbatim).

### 4.1 Surface A — durable snapshot files (existing, formalized here)

Per session dir (`getSessionDir(project, id)`); council run dirs per the v4.0 layout.

| File | Writer / when | Guarantees v4.3 pins down |
|---|---|---|
| `metadata.json` (session/leg/wave) | orchestrator, at lifecycle transitions | atomic; **additive-only evolution** (existing keys never renamed/removed/retyped); abort-wins precedence as today. v4.3 adds (additive): `retryOf`, `retriedBy[]` (wave-level), `attempts[]` (leg-level, on fallback), `usage` on continue/resume finalize. |
| `progress.json` (leg/solo) | headless poll loop / interactive mirror, on activity (~2 s granularity while healthy) | atomic. v4.3 adds (additive): `schemaVersion`, `type:'progress'`, and **`usage` raw totals** (`{tokens, costReported}` — the `sumPerMessageUsage` snapshot, written on each progress flush). Raw totals only; **cost resolution happens at read time** (`resolveUsage` + catalog), keeping the writer cheap and the pricing current. Consumers must treat staleness > 60 s with `metadata.status === 'running'` as a stall candidate (existing `isStalled`). |
| `conversation.jsonl` | mirror, append | unchanged; tail-tolerant readers only. |
| `wave.json` | fanout aggregator, once, at terminal | atomic; **immutable after write** (retry links deliberately live in metadata, §6.1). Leg docs gain additive `attempts[]` + `fallback` fields when substitution occurred. |
| `run.json` + stage artifacts (council) | v4.0 engine, checkpoint per stage | as designed in v4.0; v4.3 adds nothing to its shape beyond stage events mirroring it (§4.2). |
| pointer file `council-<runId>.json` | v4.0 engine | the id-resolution bridge `watch`/`status`/`spend --council` reuse. |

### 4.2 Surface B — the event stream: `events.jsonl`

New in v4.3. One file per **wave dir** and per **council run dir**. Append-only NDJSON,
written ONLY by the owning orchestrator process (single writer ⇒ ordering is trivially
correct; `fs.appendFileSync`, same durability tradeoff as the two existing ledgers: a torn
final line on a hard crash is acceptable and skipped by readers).

Envelope: every line is `{schemaVersion, type:'event', event, ts, id, ...payload}` where
`id` is the waveId or councilRunId the file belongs to. Event vocabulary (v4.3, complete):

| `event` | payload | emitted when |
|---|---|---|
| `wave-started` | `models[]`, `legIds[]` | after wave metadata written, before legs launch |
| `leg-started` | `legId`, `model`, `modelInput` | per leg, at launch |
| `leg-fallback` | `legId`, `fromModel`, `toModel`, `reason`, `attempt` | substitution about to launch (§6.2) |
| `leg-terminal` | `legId`, `model`, `status`, `durationMs`, `usage` | leg finalize (after metadata patch + ledger append) |
| `wave-terminal` | `status`, `counts`, `usage`, `exitCode` | after wave.json written |
| `retry-started` | `retryOf`, `legIds[]` | on the NEW retry wave, at start (§6.1) |
| `run-started` / `stage-started` / `stage-terminal` / `run-terminal` | council: stage name, status, stage `waveId` where applicable, final `exitCode` | council run.js state machine, at each checkpoint |

Deliberately **milestones only** — no token-level or stage-sample events. Live fine-grained
state (generating/folding, message counts, token totals) is Surface A's job; events are the
durable "what happened, in order" record. This keeps the writer honest (it only emits what
it directly observes), the file small (≤ a few dozen lines per run), and rotation unnecessary.

**Tail protocol (the reader half of the contract):** poll `fs.stat` at 0.5–2 s; if size grew,
read from the saved byte offset; parse only newline-terminated lines (an unterminated tail
is held until the next tick); file-not-yet-exists / transient open errors are missed ticks,
not errors. Shipped as `src/observe/events.js` (`appendEvent`, `createEventTail`).

### 4.3 Surface C — the composed live doc

The cross-file rollup that already exists as `amicus_status` (wave → legs enriched from
progress files; crash detection; council stage progression per v4.0) IS the composed
contract — v4.3 formalizes rather than reinvents it:

- Live composed docs gain an additive **`view: 'live'`** marker (plus the schemaVersion v4.0
  already adds). This disambiguates them from the terminal artifacts that share `type`
  values (the status wave payload vs `wave.json` are different shapes both typed `'wave'`
  today) **without** renaming any `type` — renaming would break `cli-handlers-status.js` and
  `mcp-wait.isTerminalSnapshot`, both of which switch on `type === 'wave'`.
- Leg entries gain `usage` (raw progress totals + read-time resolved `cost`), so live
  tokens/cost-per-leg appear in `amicus status`, `amicus_status`, `watch`, and v4.4 for free.
- Update cadence: composed on demand from Surface A; freshness = Surface A freshness.

**Consumer matrix** (all four consume identically; nothing is terminal-scrape-based):

| Consumer | Surfaces used |
|---|---|
| `amicus watch` | C for the table, B for milestone lines / history on join |
| `--follow` | B (emitted in-process, printed as it happens — no tail needed) |
| `--on-complete` | fires on the same finalize that writes `wave-terminal`/`run-terminal`; payload = file paths, not content (§5.3) |
| v4.4 GUI | C via the in-repo composition module + B via `createEventTail` + A directly |

**Schema publishing:** `schemas/` (v4.0) gains `event.json`, `progress.json`,
`wave-live.json` / `run-live.json` / `council-run-live.json` (the `view:'live'` shapes), and
the spend doc schema is extended (§7). Every new builder output is ajv-validated in tests,
same as v4.0. The two JSONL ledgers remain documented schema exclusions.

## 5. Cluster 1 — live observability terminal surface

### 5.1 `amicus watch <id>` (new command, `src/cli-handlers-watch.js` + `src/observe/`)

- **Id resolution:** wave metadata (`type:'wave'`) → wave view; council pointer file →
  council view; anything else → solo session view. `--project` as in `status`.
- **TTY default — in-place refresh table** (recommended): repaint a bounded block (ANSI
  erase-line + cursor-up; **no alternate screen**, scrollback preserved — the docker/npm
  pattern), default `--interval 2` (seconds; floor 0.5). Layout:
  - header: id, status, elapsed, legs done/total, **cost-so-far** (sum of resolved leg usage,
    `formatCost` — `~` prefix preserved so estimates can't read as authoritative);
  - one row per leg: model, coarse `phase`, msgs, `in/out` tokens, cost, sanitized
    `latestPreview` (truncated to width), `⏳stalled` flag;
  - council: stage checklist (`✓ done / ▶ active / · pending`) above the active stage's leg
    rows; recent milestone lines (from events.jsonl) in a footer.
  - *Weighed vs appending log lines:* a refresh table is glanceable and matches "watch a
    council think"; log lines survive pipes/CI and are trivially testable. **Both ship** —
    the table is the TTY default; log-lines mode is the automatic non-TTY fallback and the
    explicit `--plain` flag (milestone events + a periodic one-line rollup). The renderers
    are pure functions over the composed doc (wave-progress.js precedent), so the table adds
    no testing burden beyond string assertions.
- **`--json`:** NDJSON to stdout — tailed event lines verbatim, plus the composed live doc
  each interval **only when changed**, plus the final composed doc; exits at terminal state.
- **Exit codes:** terminal `complete`=0, `partial`=2, else 1 (waveExitCode mapping; council
  runs pass through run.json's recorded exitCode) — so `amicus watch <id> && next-step`
  works as a poor-man's wait. Watching an already-terminal run renders once and exits mapped.
- Composition reuses `handlers.amicus_status` exactly as `cli-handlers-status.js` does
  (zero duplicated rollup logic; crash detection inherited per tick).

### 5.2 `--follow` (flag on `fanout` and `council run`)

- Streams the run's own events (§4.2) as they are emitted, **to stderr** — no tailing
  needed, the orchestrator is the emitter. Format follows the run's mode: with `--json`,
  NDJSON event lines (machine-consumable; CI does `--json --follow 2>progress.ndjson`);
  in human mode, the terse per-event lines of the `--plain` formatter, replacing the 15 s
  heartbeat table. stdout keeps its existing contracts byte-identical in both modes
  (`--json` final doc; human summary). Without `--follow`, nothing changes anywhere.

### 5.3 `--on-complete` (from D6, scoped to exec + mcp-notify)

**Split by transport — this is the security posture:**

- **CLI = exec only.** `--on-complete "<command>"` on `fanout` / `council run`. The command
  is user-authored on the command line of this invocation — the same trust level as typing
  it into the shell. Amicus never sources hook commands from config, briefings, or model
  output (D8 withdrawn), and never interpolates anything into the command string.
- **MCP = notify only.** `onComplete: 'mcp-notify'` input on `amicus_fanout` /
  `amicus_council_run`. Exec is deliberately NOT exposed over MCP: a tool input that makes
  amicus run arbitrary shell commands would be a prompt-injection amplifier, and an MCP
  client that wants to run a command can already do so itself.

**Exec contract:**
- Fires once, at terminal state, strictly AFTER `wave.json`/`run.json` and the terminal
  event are durable (ordering guarantee: the hook always sees final state on disk).
- Spawn: `child_process.spawn(cmd, {shell:true, cwd: project})`; stdout/stderr → amicus
  stderr (never stdout — `--json` purity); stdin closed; hard timeout 60 s then kill
  (env-overridable `AMICUS_HOOK_TIMEOUT_MS`); non-zero exit / timeout is logged as a warning
  and **never changes the run's own exit code, docs, or events**.
- Payload via **environment only, ids and paths only — never model-generated text**:
  `AMICUS_TASK_ID`, `AMICUS_TYPE` (`wave|council-run`), `AMICUS_STATUS`, `AMICUS_EXIT_CODE`,
  `AMICUS_RESULT_FILE` (abs path to wave.json / run.json), `AMICUS_EVENTS_FILE`,
  `AMICUS_COST` (resolved amount or empty), `AMICUS_PROJECT`. A hook that wants content
  reads the result file itself. Keeping summaries/previews out of the env means untrusted
  model text can never ride into a user's shell pipeline unrequested.

**mcp-notify semantics:** for runs owned by the shared-server MCP process, at the same
finalize point that settles the in-process wait registry, the server sends an MCP logging
notification (`notifications/message`, level `info`, logger `amicus`) whose `data` is the
terminal event doc. Documented as **advisory/best-effort**: delivery and display are
client-dependent, and runs not owned by the MCP process (spawned CLI children) cannot emit
it — `amicus_wait` remains the reliable completion mechanism. No new tool; no tool-count
change from this feature.

## 6. Cluster 2 — failed-leg resilience

### 6.1 `fanout --retry-failed <waveId>`

**Approach — new linked wave (recommended).** *Weighed:* resuming the SAME wave in place
would keep one id but must mutate a terminal `wave.json` that `--json` consumers may have
already archived, collides with leg session dirs/locks, and leaves ambiguous hybrid state on
a crash mid-retry. A new wave keeps `wave.json` immutable (§4.1), preserves the full attempt
audit trail, keeps ledger attribution natural, and is mostly a thin argument-builder over
the existing `runFanout`. *Rejected:* in-place resume (mutation + lock hazards); per-leg
attempt subdirs inside the old wave (complexity without consumer benefit).

Mechanics:
- Eligible legs: terminal non-complete (`error|timeout|crashed|aborted|idle-timeout`).
  Original wave still `running` → refuse (error envelope). Zero eligible → friendly no-op,
  exit 0. Optional `--models` filters the eligible set (open question 6).
- Each retried leg relaunches with its **own saved initial context** (systemPrompt +
  userMessage verbatim from `saveInitialContext`) — a byte-identical retry with no context
  rebuild/drift; legacy legs missing saved context fall back to `briefing.md` +
  no-context prompt build, flagged in the doc. Model = the leg's original `modelInput`,
  re-routed fresh through the #61 router (a transient routing failure retries correctly).
- Linkage (all additive): new wave metadata + doc gain `retryOf: <origWaveId>`; each new leg
  metadata gains `retryOf: <origLegId>`; the ORIGINAL wave's `metadata.json` gains
  `retriedBy: [<newWaveId>, …]` (metadata is lifecycle state and already mutable;
  `wave.json` is not touched). `status <origWaveId>` surfaces `retriedBy` additively.
- `--json` consumers: the retry emits a NORMAL wave doc (existing schema) plus additive
  `retryOf` and an `effective` block — per original leg slot: latest-attempt status, and
  usage summed **across all attempts** (wasted spend stays visible); plus effective
  `counts`/`usage` rollups. Chained retries walk `retryOf` links (cycle-safe, bounded).
- Ledger: each retried leg appends its own row (`op:'leg'`, new waveId, `retryOfWaveId`
  additive) — nothing about the original rows changes.

### 6.2 Cheaper-model fallback chains (E10)

- **Config shape** (user config; per-run flags override):
  ```json
  "fallbacks": {
    "enabled": false,
    "maxSubstitutions": 2,
    "chains": { "opus": ["sonnet", "haiku"], "gpt": ["openrouter/openai/gpt-5.2-mini"] }
  }
  ```
  CLI: `--fallback` / `--no-fallback` on `fanout` and `council run`. **Default OFF**
  (recommended, open question 2): silently swapping a council seat changes bench semantics;
  substitution must be chosen, then it is loudly recorded.
- **Default chains** when a model has no explicit chain: derive from `model-tiers` —
  from the failed model's tier walk down (frontier→balanced→economy) within its vendor via
  `resolveTier` against the live catalog, dropping entries equal to the failed model.
  Gateway-only vendors (all tiers pin to one flagship) and unknown vendors get no default
  chain — the leg fails as today. Chain entries may be aliases or full ids, including
  explicit `openrouter/...` ids (so "same model, other gateway" is expressible as a chain).
- **Trigger classification** — new `src/utils/error-classify.js`:
  `classifyLegError(message)` → `rate-limit | overload | auth | timeout | other`, by
  conservative case-insensitive patterns over the OpenCode error string
  (`429|rate limit|too many requests|quota|resource exhausted` → rate-limit;
  `529|503|overload|capacity|server busy|service unavailable` → overload). Fallback fires
  ONLY on `rate-limit|overload`. Timeout is excluded (a slow model on a long task is not a
  capacity signal — open question 3); auth/validation never substitute. Misclassification
  cost is bounded either way: one extra cheaper attempt, or status quo.
- **Per-leg, not per-wave** (recommended): each leg walks its own chain independently; one
  leg's 429 must not downgrade healthy siblings.
- **Execution (in `runLeg`):** on a classified retryable failure with chain remaining and
  `attempt < maxSubstitutions`: append the attempt to leg metadata `attempts[]` (`{model,
  status, usage, startedAt, completedAt, reason}`), emit `leg-fallback`, resolve the
  substitute via `resolveRouteForLaunch` (the #61 bridge — **never** reuse the failed
  route; the substitute re-routes per current gateway rules and keys), and relaunch
  `runHeadless` in the SAME leg session dir under the SAME legId (conversation appends;
  progress reflects the current attempt; `metadata.model` = current model, `modelInput`
  stays the original).
- **Sole-input invariant respected:** chain candidates are pre-resolved at
  `validateFanoutModels` time and the UNION of primary + candidate executable ids is
  registered with the shared OpenCode server at startup (registration is config, not
  spend). A candidate that fails pre-resolution is dropped from the chain with a log line —
  never a wave failure. Substitutes are exempt from the pre-flight `--max-cost` estimate
  (they may never run) but the per-$/Mtok hard threshold applies at substitution time
  (an over-cap substitute is skipped to the next entry).
- **Ledger attribution of the substitute:** one row per attempt — the failed attempt's row
  carries the ORIGINAL model + its partial usage + `status`; the substitute's row carries
  the substitute model + `substitutedFor: <originalModel>` + `attempt: N`. Wave/leg docs:
  final leg `usage` = **sum across attempts** (nothing hidden); `attempts[]` breaks it down;
  leg `fallback: {from, reason, attempts}` summarizes.
- **Council interplay:** when enabled on a council run, chains apply to stage legs via the
  same runLeg path. `runStats[].model` and `meta.models` record the model that actually
  reviewed (street-cred attributes to the actual reviewer); the chair remains excluded as
  in v4.0; substitutions are listed in run.json and the report. Chair legs never substitute
  via chains — the chair has its own v4.0 fallback-promotion path already.

### 6.3 Failed-leg partial-spend tracking (E8)

- Reality check (verified in source): failed/timed-out legs ALREADY append ledger rows with
  their partial token usage — `runHeadless` returns `usage` on its error paths and
  `fanout-leg.js:120-129` appends whenever a usage object exists. The gap is that these rows
  are indistinguishable from healthy spend.
- Fix: every row gains `status` (the run/leg terminal status; §7). Rollups gain a `wasted`
  view: total + per-status breakdown over rows with `status !== 'complete'`, surfaced as an
  additive `wasted` block in the spend doc and one line in the human rollup
  (`Wasted (failed runs): ~$0.42 across 7 rows — see amicus spend --failed`).
- All-zero rows (e.g. setup-throw legs) keep appending — with `status` they become "N failed
  runs, $0 recorded" visibility instead of noise.

## 7. Cluster 3 — spend visibility & attribution (basic)

### 7.1 Row schema (spend-ledger.jsonl — internal v1, additive fields only)

Current row: `{schemaVersion:1, ts, taskId, waveId, model, mode, tokens, cost}`. v4.3 adds:

| field | value | closes |
|---|---|---|
| `op` | `start \| continue \| resume \| leg` | C9/E4 (rows exist at all for continue/resume) |
| `status` | run/leg terminal status | E8 |
| `councilRunId` | from the v4.0 engine's launches (stage legs AND chair/repair solos), else null | E9/D7 |
| `councilName` | preset name when launched via `--council <preset>`, else null | E3 |
| `project` | absolute project dir | E3/D7 |
| `gateway` | `direct \| openrouter` from route provenance | attribution (FinOps: gateway fees) |
| `attempt`, `substitutedFor`, `retryOfWaveId` | fallback/retry linkage, else absent | E10/E8/F2 |

Old rows simply lack the new fields → readers treat them as unattributed (grouped under
`(unattributed)`), never skipped. `SPEND_LEDGER_SCHEMA_VERSION` stays 1 (additive within a
version, per the stability contract). `mode` keeps its existing meaning
(`headless|interactive|leg`).

### 7.2 Closing the continue/resume zero-spend gap (C9/E4)

Mirror the start.js finalize pattern at both finalize sites (`continue.js`, `resume.js`,
which the MCP handlers also route through): `resolveUsage({model, usageTotals:
result.usage})` → write `usage` into the session metadata (buildRunResult already surfaces
`metadata.usage`, so `--json` run docs gain it for free) → `appendSpend` with
`op:'continue'|'resume'`. Both transports are covered — `runHeadless` and the interactive
mirror both already return usage totals; only these finalize paths drop them today
(BACKLOG.md:280). The v4.0 engine's chair/repair **solos** get the same treatment via its
run-launch wrappers with `op:'leg'` + `councilRunId` set (they currently bypass every
appendSpend call site — without this, council chair spend is invisible).

### 7.3 Query surface

**CLI (recommended shape): extend `amicus spend` with flags — no `spend query` subcommand.**
*Weighed:* a subcommand is a second entry point over the same rows with its own help/tests;
flags keep one command, stay byte-compatible when unused, and satisfy D7's "queryable"
verbatim. New flags: `--wave <id>`, `--council <runId|name>`, `--project <path|.>`,
`--model <id-or-prefix>`, `--failed` (rows with status ≠ complete), `--op <op>`,
`--group-by model|wave|council|project|op|day` (default `model` — today's behavior),
`--rows` (include matching raw rows in the doc, capped at 1000 with `rowsTruncated:true`).
Spend doc (result family, additive): keeps `total`/`byModel` exactly as today, adds
`filters`, `groupBy`, `groups[]` (the requested dimension), `wasted`, and `rows?`.

**MCP:** one new read-only tool **`amicus_spend`** mirroring the flags (recommendation —
open question 1; conservative fallback: ship CLI-only). Rationale vs the 52→13 de-bloat
invariant: that purge removed REDUNDANT tools; spend data is otherwise unreachable from
MCP-only hosts (Cowork has no shell), it is read-only, and one tool covers all of D7.
Tool count 15 → 16. **No fence needed and none added:** spend docs contain no
model-generated text by construction (ids, numbers, paths) — and the schema commits to
keeping it that way (no previews in rows, ever).

## 8. Error handling

- **Reads:** every consumer treats missing files, unparseable JSON, torn tails, and
  transient Windows open errors as missed ticks (degrade, retry next poll) — the
  mcp-wait/readLegState posture, now stated as a contract rule (§4). A watch that NEVER
  sees a valid snapshot before its first render window reports the id as
  unknown/unreadable and exits 1 through the error envelope.
- **events.jsonl absent** (pre-v4.3 runs, solo runs): watch degrades to snapshot-only
  (no milestone footer/history); `--json` watch emits snapshots only. Not an error.
- **Hooks:** exec failure/timeout → stderr warning + log, run outcome untouched;
  mcp-notify send failure → debug log only. Hook stdout can never contaminate `--json`.
- **Fallback:** substitute route-resolution failure → skip to next chain entry; chain
  exhausted → leg fails with the ORIGINAL error (attempts recorded); classifier `other` →
  no substitution. Fallback bookkeeping (events, attempts, ledger) is best-effort and can
  never fail the leg (appendSpend's never-throws guarantee extended to appendEvent).
- **Retry:** original wave running → refuse pre-flight through the error envelope; a
  still-locked leg session fails only that leg (routing-failure-leg pattern); a crash
  mid-retry leaves a normal partial retry wave — itself retryable.
- **Spend query:** corrupt rows skipped (existing); unknown `--group-by`/flag values fail
  through `failJson` with hints; empty result sets emit valid zero docs.
- **Clocks/durations:** all durations derive from recorded ISO pairs (`durationBetween`),
  never wall-clock deltas across processes.

## 11. Resolved questions (Christian, 2026-07-19)

**Decision: all recommendations below adopted as written** (amicus_spend MCP tool added 15→16;
fallback opt-in, capacity-signals-only; retry --models filter in; 2s watch default; wasted
bucketed by status; street-cred attributes to the actual model; view:'live' additive marker).
Q&A preserved verbatim for the rationale record.

1. **Add the `amicus_spend` MCP tool (15 → 16 tools), or ship spend query CLI-only?**
   *Recommendation: add it.* The 52→13 de-bloat killed redundant tools; this one is
   read-only, single, and covers data otherwise unreachable from MCP-only hosts (Cowork has
   no shell). If the count itself is the invariant you want to defend, CLI-only loses only
   agent self-service cost checks — everything else in this spec stands unchanged.
2. **Fallback chains default: opt-in (`--fallback`/config) or on-by-default for plain
   fanout?** *Recommendation: opt-in in v4.3.* Substituting a seat silently changes what
   "the council said" means; let it earn trust loudly first, revisit default-on for
   non-council fanout in 4.4 once substitution reporting has been seen in the wild.
3. **Should leg TIMEOUT also trigger fallback, or only rate-limit/overload?**
   *Recommendation: no — capacity signals only.* A timeout often means the task is heavy,
   and a cheaper model retried on it converts a slow answer into a worse one;
   `--retry-failed` covers timeouts deliberately. Easy to widen later (one classifier line).
4. **`--retry-failed --models <subset>` filter: include in v4.3 or YAGNI?**
   *Recommendation: include.* It is a trivial filter over the eligible set, and "retry the
   two OpenRouter legs but not the direct leg that failed on auth" is a predictable first
   real-world need.
5. **Watch default interval 2 s (matches mcp-wait poll cadence) — happy?**
   *Recommendation: yes, with `--interval` down to 0.5 s.* File polling cost is negligible
   either way; 2 s keeps watch and MCP status telling the same story at the same rhythm.
6. **`wasted` spend definition: every non-`complete` row, including `aborted`?**
   *Recommendation: yes, but bucketed by status* in the doc — an abort you chose reads
   differently from a rate-limited death, and the breakdown keeps both honest without a
   second definition.
7. **Council seats substituted by fallback enter street-cred as the ACTUAL model
   (substitute), with the swap recorded in run.json + report — agreed?**
   *Recommendation: yes.* Street-cred must attribute to whoever actually reviewed;
   anything else poisons the reliability ledger. The recorded `leg-fallback` event +
   `attempts[]` keep the original intent auditable.
8. **Disambiguating live docs via additive `view:'live'` (keeping `type:'wave'`), rather
   than renaming status doc types — agreed?** *Recommendation: yes.* Renaming types would
   break `cli-handlers-status` and `mcp-wait.isTerminalSnapshot` switches plus any external
   consumer; the additive marker gives v4.4 unambiguous schemas at zero migration cost.
