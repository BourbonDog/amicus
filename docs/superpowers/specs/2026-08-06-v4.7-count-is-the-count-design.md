## §3 Facts established at kickoff (verified at `bf1fa4d` — do not re-derive)

### 3.1 The chair-cost question is answered: PARTIAL — a third row class

- A failed chair attempt's usage never reaches runStats: `run-chair.js:107` returns
  `leg: ok ? solo.leg : null` (the failed leg — which may carry real usage — is discarded from
  the stats path; `rawLeg` retains it for outcome classification only), and `run.js:237-244`
  builds the ONLY chair row from the successful `chairLeg`.
- The money is NOT dropped: every attempt is `addWave`'d (`run-chair.js:102`, ch4 at `:197`),
  so it reaches run.json's terminal `usage` block (`run-finalize.js:101` ← `run-budget.js`
  `usageBlock()` over ALL legs) and `spend-ledger.jsonl` (`fanout-leg.js:210`
  `recordAttemptSpend` on every leg, `councilRunId`-attributed via `run-chair.js:100`).
- **Consequence: run.json's total and Σ(tally.runStats) silently disagree by exactly the
  omitted spend.** Proven on a real artifact: `.superpowers/sdd/v462p4/council-12c96b6b/` —
  tally rows sum \$0.047737774 vs run.json usage \$0.048829594, a \$0.00109182 divergence from
  a repair leg. The GUI shows both numbers on one panel (rows from tally at
  `workspace/run-detail.js:73`, total from run.usage at `:81`).
- Cross-foot sanity: `.superpowers/sdd/v462p5/council-120636cb/` (nothing failed) — the five
  runStats costs sum to run.json's \$0.084520289 EXACTLY. The identity holds when no leg is
  omitted; the design makes it hold always.

## §5 CA-4 design — row per launch

**D1 — Leg–row bijection (the invariant's structural form).** Every leg the budget counts
(`addWave`) appears on exactly ONE runStats row. Corollary: Σ`sumWaveUsage(runStats)` ≡
run.json's usage block — cost amount AND the reported/estimated/unpriced/subtreeUnknown
counts — for every terminal run.

**D2 — Row classes.** Primary rows (exactly one per requested reviewing seat) keep today's
roles: `seat`, `critic`, `lens:<slug>`, `judge`, `chair` (wasChair true), synthetic `claude`.
#83's honest-error-row treatment extends to ALL seats: a dead seat/critic/lens with no
recovery gets a primary error row built from its dead leg (usage attached — improving the
ledger's currently-fabricated `conformance: 'clean'` default for dead seats,
`ledger.js:29`). A chair walk that gives up entirely gets a primary error `chair` row for the
REQUESTED chair alias with `usage: null` (each attempt's money rides its own attempt row —
no double count). Non-primary rows (new roles): **`chair-attempt`** (failed ch1–ch3, built
from the already-retained `rawLeg`), **`repair`** (Stage-1 `-p`, Stage-2 `-q`, chair ch4
solos), **`superseded`** (SL-2 dead first legs; debate pre-repair originals — `run-debate.js`
must retain both legs, hence its PR0 extraction). `wasChair` stays false on every non-primary
row.

**D3 — `waveId` on every row**, emit-only-when-set (old fixtures stay byte-compatible; the
tally allowlist at `tally.js:115` gains the field). Every row is auditable back to its leg;
the invariant test joins on it. No `for`/seat-link field (considered-not-done — waveId +
run.json already encode it).

**D4 — Fail-closed consumers.** The ledger join (`ledger.js:24`) flips from a skip-set
(judge + DEBATE_ROLES) to an explicit **ledger-join allowlist** (`seat`, `critic`,
`lens:*`, `chair`, `claude` — judge stays excluded per #83's overwrite-guard, so the
allowlist is primary-roles-minus-judge) and no future role can corrupt reliability stats.
The GUI seats derivation (`seatsFromRunStats`) already carries #108's reviewing-role
allowlist — the plan VERIFIES the new roles are excluded by it and adds a pin if any
slips through (a failed chair attempt must never materialize as a ghost seat row). Both
pinned by tests (a non-primary row must never produce a ledger row or a seat).

**D5 — The invariant test.** New suite asserting D1's sum identity over: the engine e2e
fixture runs, a reconstructed `12c96b6b`-shaped fixture (repair divergence — the regression
case), and a chair-walk-failure fixture. RED-provable by reverting any single row source.

**D6 — Surfaces.** Report per-row table renders non-primary roles with the existing suffix
pattern (`(judge)` precedent); `council tally` human line now sums complete rows; the GUI
costPanel's rows now sum to its own total (the two-numbers-disagree symptom dies). MCP
`amicus_council_tally` output is additive-only.

**D7 — Not touched:** `chairAttempts[]` shape (schema + lockstep test stay as shipped);
`MANUAL-ORCHESTRATION.md` gets a note that skill-authored tallies may carry seat-primary rows
only (tolerant readers; no contract change).

## §6 GOA-7 prerequisite design — resolved-id ledger, legacy-read

**D8 — `resolvedModel` threading.** `buildRunStatsEntry` gains `resolvedModel: leg.model`
(the executable id), emit-only-when-set — all callers get it free; the `claude` row and the
give-up chair error row have none. Through the tally allowlist onto every runStats row (this
also future-proofs CA-4's new rows: attempt/repair rows carry what actually served).

**D9 — Ledger schema bump.** Ledger rows gain `resolvedModel`; `LEDGER_SCHEMA_VERSION` 1→2.
No other fields (the F3 no-drive-by discipline; seat-id ≠ model-id explicitly NOT taken —
recorded as considered, it belongs to a self-ensemble rev). Absent `resolvedModel` ⇒ legacy
row (R2). Append-only survives; no migration.

**D10 — Two-mode aggregation.** `deriveReliability` groups by `row.resolvedModel ||
row.model`. Aggregate rows carry `aliases[]` (every alias observed for that key) and
`legacy: true` on alias-keyed groups. `council stats` (CLI human render + `--json`/MCP,
additive `council-stats.schema.json` fields) marks legacy rows visibly — history splits at
the bump, honestly; a retargeted alias's new rows naturally start `lowN` (the GOA-5 scout
treatment the BACKLOG anticipates).

**D11 — The chair-picker seam (the one subtle spot).** `pickFallbackChair` and
`run-server.js:128` consume aggregates and launch the result directly. Post-rekey: exclusion
must test bench membership against the row's key AND its `aliases[]`; the launched name must
remain routable (the most-recent alias, falling back to the resolved id — the router accepts
both). Pinned by tests: bench exclusion must not regress; the promoted chair must launch.

**D12 — Docs.** `docs/schemas.md:52` rewritten (the ledger is now versioned, v2 current,
legacy-read rule stated); `docs/council.md:549` runStats row inventory updated for §5's
roles.

## §7 F8 design — tags, search, one list

**D13 — `--tag <t>`** on `start`, `fanout`, `council run` (CLI + MCP inputs). Validation
mirrors `sanitizeCouncilName` (64-char cap, safe charset; reject otherwise). Stored
absent-not-null at all four sites (solo metadata, wave metadata, run.json seed via
`run-state.js:97` spread — zero `run.js` change, council-run doc). Flag registered by adding
it to the `cli.js` usage blocks (known-flags derives from usage text). Additive on result
docs per the schema stability contract — no schemaVersion bumps.

**D14 — List unification.** `read.js` `enumerateSessions` becomes the single enumeration
both the CLI and MCP `amicus_list` consume (the MCP path keeps its council-pointer merge and
sanitized previews). Fixes the dead `--all` flag as part of the unification. Human `list`
output gains a TAG column; MCP rows gain `tag`.

**D15 — `--search <q>`** on `amicus list` + MCP `amicus_list`: case-insensitive substring
over id, tag, and briefing text (already stored — full prompt on solos, 200-char excerpt on
waves, `briefing.md` on council runs). No index, no new storage.

**D16 — Grouped history.** `spend` leg rows gain `tag` stamping at the write site;
`GROUP_DIMS` gains `'tag'` (CLI validation + MCP Zod schema update in lockstep — the enum is
single-sourced). **Cuttable at plan time** if the spend write-path measures worse than the
2-file trace; the cut line is recorded here so cutting it is a tick, not a re-litigation.
