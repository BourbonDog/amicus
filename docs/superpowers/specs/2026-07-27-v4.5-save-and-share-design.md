# Amicus v4.5 — "Save and share your councils" (Design)

**Status:** DRAFT — awaiting Christian's review
**Baseline:** shipped **v4.4.1** (2026-07-27), `main` = `66ff750`, 446 suites / 5,718 passed, **16 MCP tools**. The engine has: headless council + debate (v4.0/v4.1), local providers + `'local'` gateway (v4.2), the observability data layer + `watch`/spend attribution (v4.3), the Council Workspace GUI (v4.4), cost-truthfulness + repair-path integrity (v4.4.1).
**Supersedes:** `2026-07-19-v4.5-policy-packs-composition-design.md` (scope split 2026-07-27: this rev = save/share; **v4.6 "Compose your councils"** = chained waves (F6) + tagging/search (F8) + GUI power ergonomics (F10), specced after v4.5 ships). The 7/19 spec's **Resolved questions (Christian, 2026-07-19) remain authoritative** and are restated here where they apply — they are carried decisions, not re-opened ones.
**Inputs:** `docs/ROADMAP.md` v4.5 entry + "Design notes — auto-open the Council Workspace" (recorded 2026-07-26) + "Deferred out of v4.4.1 into v4.5" table; root `BACKLOG.md` (FR-1/2/3, refuted-findings register); `.superpowers/sdd/v44/v4.4.1-backlog.md` (RN item detail, Appendices A/B).
**Release:** ships as **v4.5.0** on the 4.x line. **Aggregate effort: M** (biggest piece: pack resolution/merge).

## 1. Goal / benefit

Councils you can **save, share, and re-run as one command** — and the flagship GUI stops hiding:

1. **Policy packs (B7/F5):** a named, versioned, shareable JSON artifact capturing everything a run needs — bench + chair + critic/lenses + options + a briefing-template reference — invoked as `--pack <name|path>` on `council run`, `fanout`, and `start`. Every run records the resolved pack name+version+hash.
2. **Briefing templates (F9):** reusable `{{variable}}` templates with a built-in library, referenced by packs or `--template`.
3. **★ Auto-open the Council Workspace:** a council launched from Claude Desktop over MCP opens the v4.4 Workspace window automatically (guarded, opt-out) instead of requiring a separate `amicus watch <runId> --ui` nobody discovers.
4. **Ride-along fixes:** FR-1 (a failed council seat can render as perpetually live), an explicit FR-2 ruling, and three S-sized Workspace renderer fixes (RN-1/RN-5/RN-11) in the files this rev already touches.

## 2. Non-goals

- **Chained waves / `--input-from` / digests / stdin pipe (F6), tagging + `--search` + grouped history (F8), GUI power ergonomics (F10)** — moved to **v4.6** (decision 2026-07-27). The `{{input}}` template variable is NOT in v4.5's variable set; v4.6 introduces it with `--input-from` (a template using it on v4.5 gets the standard unknown-variable error, which is accurate). The `critique`/`refine` built-in templates are `{{input}}`-centric and ship with v4.6; v4.5 ships `review` only.
- **Team config cascading / `.amicusrc` (A9)** — v5.0. Packs must not preclude it (they don't; a future `.amicusrc` can add pack directories). Repo/team sharing in v4.5 is `--pack <path>` — commit the file.
- **Pack registries / marketplaces / remote install** — sharing is "send or commit the file."
- **Calibration-driven seat selection (B4/B5)** — packs are static declarations.
- **Pack-encoded verdict thresholds / evidence requirements / model notes / debate-rule DSLs** — no engine hooks; dead config. (B7 long tail, dropped.)
- **Auto-open on the CLI path.** `detectClient` only works on the MCP path (it reads the MCP client's `getClientVersion().name`); a terminal `council run` has no MCP server. CLI users keep explicit `amicus watch <id> --ui`. Do not thread a client tag through the CLI for this.
- **Auto-install of Electron** — auto-open requires Electron already present, full stop.
- **`--json` / envelope changes beyond additive fields** — schema families stay at v2; one new published doc type (`pack`).

## 3. Carried decisions (Christian, 2026-07-19 — restated, not re-opened)

1. **One noun: "pack"** — B7 packs and F5 run-profiles are one artifact with `kind: "council" | "fanout" | "solo"`; one flag (`--pack`), one management family (`amicus pack …`).
2. **Packs are files** — one JSON per pack in `~/.config/amicus/packs/` (honors `AMICUS_CONFIG_DIR`), invocable by name or path.
3. **Precedence: explicit CLI flag > pack field > `config.json` default > built-in**, for every knob including the bench (`--models`/`--council` beat `pack.bench` with a stderr notice). Runs record both the pack reference and resolved effective values.
4. **Legacy `councils.<name>` presets kept, not migrated** — packs compose with them (`"bench": "budget"` resolves through `resolveCouncilMembers` at run time; `src/utils/config.js:421` verified on `66ff750`).
5. **Solo packs in scope** (`kind:"solo"` on `amicus start`).
6. **`pack save` auto-bumps patch** when content changed and `--version` omitted; content hash is the tamper-proof anchor.
7. **Variable expansion only in template files** — `--prompt`/`--prompt-file` text is always literal.
8. **No new MCP tools.** *(Delta from 7/19: the count is now **16**, post-v4.3 `amicus_spend` — stays 16.)* New capability = additive params on `amicus_start`/`amicus_fanout`/`amicus_council_run`.
9. **Pack `options` capture the `debate` boolean** *(delta resolved: v4.1 shipped debate, so the conditional is settled — it's in).* `--claude-review` stays deliberately NOT pack-able (per-run material).

## 4. Cluster 1 — Briefing templates (F9) *(S–M)*

Unchanged from the 7/19 spec §6.1 except the `{{input}}` carve-out:

- **Location:** `~/.config/amicus/templates/*.md` (peer of `packs/`); name = basename sans `.md`. `--template <name|path>` on `start`, `fanout`, `council run`; packs reference via `briefing.template`.
- **Variables (v4.5 set):** `{{prompt}}`, `{{artifact}}` (content of `--artifact <file>`, 256 KB cap), `{{artifact_path}}`, `{{date}}`, `{{project}}`, `{{var.<key>}}` (repeatable `--var key=value`). Whitespace-tolerant. **No `{{model}}`** (prompts are built once per wave). **No `{{input}}` until v4.6.**
- **Strict render rules** (template-mode only): unknown variable → error listing known ones; slot without data → error; data without slot → error ("would be silently dropped"); unused `--var` → notice. No template → no expansion anywhere.
- **Built-ins:** `review` only in v4.5 (artifact review with criteria slot), shadowed by a user file of the same name (built-in-bench precedent). `critique`/`refine` ship with v4.6's chaining.
- **Management:** `amicus template list [--json]` / `template show <name|path>` (built-ins marked, shadowing marked). No `template save/rm` — it's a folder of Markdown; your editor is the manager.
- **Recording:** `promptMeta` gains `"template": {"name", "hash"}` (additive); the wave/session `briefing.md` on disk is always the **rendered** text (load-bearing for v4.6's `--search` and for replay honesty).

## 5. Cluster 2 — Policy packs (B7/F5) *(M)*

As the 7/19 spec §4 with the noted deltas. Restated in full so this spec stands alone:

### 5.1 The artifact

```json
{
  "schemaVersion": 1,
  "type": "pack",
  "name": "sec-review",
  "version": "1.2.0",
  "kind": "council",
  "description": "Security-focused adjudicated review for PRs and specs",
  "bench": ["deepseek", "qwen-coder", "openrouter/mistralai/mistral-large"],
  "chair": "gpt",
  "critic": "deepseek",
  "lenses": null,
  "options": { "timeout": 10, "maxCost": 2.0, "gateway": "auto", "agent": "Plan",
               "thinking": "medium", "summaryLength": "normal", "debate": false },
  "briefing": { "template": "review" }
}
```

- `kind:"council"` as above; `bench` is inline `string[]` **or a string** naming a saved council / built-in bench, resolved at run time. `kind:"fanout"`: `bench` + options (adds `noContext`, `contextTurns`, `contextMaxTokens`); no chair/critic/lenses. `kind:"solo"`: `model` instead of `bench` (+ fanout options; UI-suppression option name verified at Task 0 against the shipped `start` flag set).
- Kind matching is **strict** (`PACK_KIND_MISMATCH` pre-flight error) — make two packs if you want both shapes.
- `version` is user-owned semver; the **content hash** (sha256 over canonical form — parsed object, sorted keys — first 12 hex) is the truth anchor, recorded on every run.
- `options.gateway` accepts the post-v4.2 value set including `'local'` *(delta from 7/19)*.

### 5.2 Storage & resolution

One JSON file per pack in `<configDir>/packs/<name>.json`. `--pack <value>`: contains a path separator or ends in `.json` → **path** (cwd-relative); otherwise **name** (`/^[a-z0-9][a-z0-9._-]{0,63}$/i`) resolved in the packs dir. Name-invoked packs must have `name` == basename (save enforces; load errors on mismatch); path-invoked packs' embedded `name` is authoritative for recording.

### 5.3 CLI surface

```
amicus council run --pack <name|path> --prompt-file b.md [overriding flags…]
amicus fanout      --pack <name|path> --prompt-file b.md [overriding flags…]
amicus start       --pack <name|path> --prompt "…"       [overriding flags…]

amicus pack save <name> --kind council --bench a,b,c|--bench <councilName>
    [--chair m] [--critic m | --lenses s1,s2,…] [--timeout N] [--max-cost N]
    [--gateway mode] [--agent Plan|Build] [--thinking lvl] [--template <name|path>]
    [--version 1.0.0] [--description "…"] [--json]
amicus pack save <name> --kind fanout … | --kind solo --model <alias|id> …
amicus pack save <name> --from-run <taskId|waveId|councilRunId> [--version …]
amicus pack list [--json] · pack show <name|path> [--json] · pack rm <name> [--json]
```

- `--from-run` snapshots a past run's resolved configuration from `run.json` / wave+leg `metadata.json` — briefing text is NOT captured (templates are for that); the saved pack has no `briefing` unless the run recorded a template reference.
- `pack save` on an existing name: unchanged content → no-op notice; changed without `--version` → auto-bump patch with notice.
- New `src/pack/` module family — `pack-store.js` (read/write/hash), `pack-validate.js`, `pack-resolve.js` (merge), `src/cli-handlers-pack.js` — all under the 300-line gate; `bin/amicus.js` gains one lazy `case 'pack'`.

### 5.4 Precedence & merge (exact)

Flag > pack > config default > built-in, per knob. "Explicit" = typed on the command line: the parser gains an **`argsExplicit` set** (keys actually seen in argv) because `parseArgs` pre-seeds defaults (`timeout: 15`, `summary-length`, `context-*`) — without it a pack's `timeout` could never win. Bench override prints the stderr notice; `--models`/`--council` still XOR each other; at least one bench source must exist. On `start`, `--model` beats `pack.model` silently (routine). v4.0 pre-flight validation runs **after** merge on resolved effective values (≥2 seats, chair ∉ bench, critic ∈ bench, critic XOR lenses, lens count == seat count, enums, positive numerics) and fails through the envelope pre-spend.

### 5.5 Legacy `councils.<name>`

`--council` keeps working unchanged; `amicus council save|list|show` keep working (`council save` help gains one pointer line to `amicus pack`). Packs reference benches rather than replacing them. No migration, no deprecation.

### 5.6 Validation

Runs at `pack save` (hard-fail), `pack show` (reports, never fails), and run-time resolve (hard-fail through envelope, pre-spend). Structural checks; seats resolvable (aliases via effective alias set, `/`-form ids pass through; bench-by-name via `getCouncilWithSource`); council rules (inline bench checked at save; by-name bench + lenses deferred to run time and reported as such by `pack show`); kind-appropriate fields only; `briefing.template` resolvable (warning at save — packs travel to machines without the template; error at run time). New published schema `schemas/pack.schema.json` (draft 2020-12) beside the existing published set — **Task 0 must count the current `schemas/` inventory and bump `schemas.test.js`'s file-count guard** (it is hardcoded and has broken on schema additions before).

### 5.7 Run recording (additive)

Council `run.json` + wave `metadata.json`/`wave.json` + solo session `metadata.json` gain `"pack": {"name", "version", "hash", "source": "dir"|"path"}`; surfaced by `read --json`/`status --json`. No pack → field absent (not null-stuffed), preserving byte-stability.

### 5.8 MCP surface

`amicus_council_run`, `amicus_fanout`, `amicus_start` each gain `pack?: string` (same semantics as CLI). Tool count stays **16**; descriptions gain one sentence each.

## 6. Cluster 3 — ★ Auto-open the Council Workspace *(S–M)*

**Behavior:** when a council run launches via MCP `amicus_council_run` and the client is Claude Desktop-class, the Workspace window opens on the new run automatically. CLI `council run` is untouched (see Non-goals).

**Seams (verified on `66ff750`):** window launch = `launchWorkspaceWindow({project, runId})` (`src/sidecar/workspace-window.js`, invoked today at `src/cli-handlers-watch.js:98-99`); client = `detectClient(mcpServer)` (`src/utils/client-detect.js`, already imported and threaded as `--client` at four `src/mcp-server.js` call sites); Electron presence = `isElectronUsable()` / `resolveElectronBinary()` (`src/sidecar/electron-install.js:87/:65`). The auto-open decision itself lives in a pure helper (`src/sidecar/workspace-auto-open.js`, `shouldAutoOpenWorkspace(ctx) → {open, reason}`) so the guard matrix is unit-testable without Electron; the MCP council-run handler calls it once, post-launch.

**The four guards (all load-bearing, all tested):**
1. **Never under `--json`:** structurally satisfied — the trigger exists only on the MCP path, which has no `--json`; the CLI path (where `--ui` already rejects `--json`) never auto-opens. A test pins that the CLI handler contains no auto-open call.
2. **Never headless/CI:** gate on the same display check the e2e suite uses (`HAS_DISPLAY` pattern). A popped window on a runner is a hang.
3. **Never trigger an install:** `isElectronUsable()` only; absent → silent no-op (`reason:"electron-absent"`). No download, no prompt.
4. **Opt-out:** config key `workspace.autoOpen` (default `true`; `false` disables) + per-call MCP param `ui?: boolean` on `amicus_council_run` (absent → config+guards decide; `false` → suppress; `true` → attempt, still guard-checked). Precedence: param > config > default — the house precedence rule.

**Client gating:** `detectClient(mcpServer) === 'code-local'` (the Claude Desktop mapping). `cowork`/`code-web` do not auto-open.

**Failure posture:** fire-and-forget. A `launchWorkspaceWindow` failure is swallowed to a structured stderr notice and never fails, delays, or aborts the council. The MCP response gains additive `workspaceOpened: boolean` (+ `workspaceOpenReason` when false) so behavior is observable rather than mysterious.

## 9. Error handling (consolidated)

All new failures route through `failJson`/`buildErrorDoc` (stdout under `--json`, exit 1, pre-spend). Additive `ERROR_CODES`: `PACK_NOT_FOUND` (hint: `amicus pack list`), `PACK_INVALID` (names exact fields), `PACK_KIND_MISMATCH` (states pack kind + accepting command), `TEMPLATE_NOT_FOUND` (hint: `amicus template list`), `TEMPLATE_RENDER` (lists known variables / the missing slot). `BAD_ARGS` reused for `--var` without `k=v`. Auto-open is **never** an error path — failures degrade to the stderr notice + `workspaceOpened:false`. *(The 7/19 `INPUT_SOURCE_*` family moves to v4.6 with chaining.)*
