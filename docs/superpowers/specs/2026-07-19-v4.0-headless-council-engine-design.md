# Amicus v4.0 — Headless Council Engine + Trust Fixes (Design)

**Status:** finalized (approved in-session 2026-07-19)
**Baseline:** v3.2.3, main `a664857`
**Inputs:** `docs/ROADMAP.md` (locked 4.x line, 2026-07-18); enhancement-council proposals
B1/A2/D2/F1/C4 (engine), B2 (Action v2), D3/C3 (envelope), A5/C6/D5 (JSON fencing),
C5/D4 (fold nonce). Council artifacts: vault `output/amicus-enhancements-council/`.
**Release:** ships as **v4.0.0** (major).

## 1. Goal

A deterministic, headless council orchestration engine — `amicus council run` (CLI) and
`amicus_council_run` (MCP) — that executes Stage 1 independent reviews → anonymized peer
cross-review → tally → chair synthesis → verdict/report **without a Claude runtime**, plus the
three trust fixes that make its output automatable (unified JSON envelope + published schemas,
prompt-injection fencing on JSON MCP tools, fold-nonce residual closure), and **Council Review
GitHub Action v2** producing a real adjudicated verdict on PRs.

The engine reuses the existing pure primitives unchanged (`validateFindings`, `tally`,
`buildVerdict`, report renderers, ledger, fanout transport). What it adds is the **conductor**
that today exists only as skill prose (SKILL.md Stages 1–3+5): stage sequencing, bundle
assembly, anonymization, id rewriting, output parsing, chair invocation, artifact
materialization.

## 2. Non-goals

- **Debate mode (Stage 2.5) headless** — deferred to v4.1 (or v4.2 at the latest).
- **Interactive skill rewire** — the second-opinion skill keeps its manual orchestration in
  v4.0; the skill-on-engine fast path is the v4.1 headline. SKILL.md gets only a short
  pointer for headless contexts.
- **Stage-4 decision automation** — the engine is report-only; it never fabricates
  accept/deny decisions. `amicus council verdict --decisions` remains the post-hoc path.
- **Policy packs / chair-in-preset** (v4.7), **observability streaming / watch** (v4.5),
  **`--dry-run` cost preview** (backlog).
- **`--json` modes for interactive-only commands** (`setup`, `update`, `key`) — documented
  envelope exclusions.

## 3. Locked decisions

1. **Scope:** core loop + chair verdict scale (always on headless) + `--critic` + `--lenses`.
   Debate deferred.
2. **v4.0 is engine + CI only**; skill fast path lands v4.1 (user: "lots of this should get
   rolled into a 4.1, or at least prior to a 4.2").
3. **Architecture:** run-directory state machine in-process (Approach 1); not script-over-CLI,
   not pure-JSON briefings — prose reviews + trailing JSON blocks stay the leg contract.
4. **Stage-4 policy:** report-only; consumers gate on tiers + chair verdict line.
5. **Chair:** `--chair <model>`, default `deepseek`; error-with-hint if chair ∈ bench.
6. **Envelope:** two schema families remain, unified on a `{schemaVersion, type}` convention;
   council family bumps 1→2; additive field injection, no re-nesting.
7. **Fencing:** outer `fenceSidecarOutput` fence on council JSON MCP tool text (same pattern
   as `amicus_read`); CLI `--json` stays byte-identical.
8. **Action v2 gating:** `fail_on` input, default `none` (report-only); gating is opt-in.
9. **Version:** 4.0.0 major (fenced MCP council JSON, `council stats` shape change,
   `--json` error-path stream changes).

## 4. CLI contract — `amicus council run`

```
amicus council run --prompt-file <briefing.md>
    (--council <preset> | --models a,b,c)   # ≥2 seats, XOR (fanout semantics)
    [--chair <model>]                       # default deepseek; must NOT be a bench seat
    [--critic <model>]                      # must BE a bench seat; adversarial brief
    [--lenses s1,s2,...]                    # count == seat count; forces no-ledger
                                            # --critic and --lenses are mutually exclusive
                                            # in v4.0 (combo semantics undefined in the skill)
    [--out-dir <dir>]                       # default ./council-<runId>/
    [--json] [--max-cost <usd>] [--timeout <min>]
    [--gateway auto|direct|openrouter] [--no-validate-model]
```

- `--prompt-file` required (no inline `--prompt`; councils always have real briefings —
  same rationale as MCP fanout's briefing-via-file).
- Seat/chair/critic/lens validation happens pre-flight and fails through the error envelope
  (exit 1) before any spend.
- `--timeout` is the **per-leg** timeout forwarded to fanout/solo legs (existing semantics).
  No separate run-level watchdog in v4.0 — CI job timeouts cover the aggregate.
- `--max-cost` is a **whole-run** ceiling: cumulative usage is checked before each paid stage
  launch (Stage 1 wave, repair solos, Stage 2 wave, chair solo). Ceiling hit mid-run: stop
  launching, finalize what exists (see degradation), never abort in-flight legs for cost.
- Signals: SIGINT/SIGTERM abort the active wave/solo via the existing abort path, finalize
  `run.json` as `aborted`, exit 130/143.
- `amicus abort <councilRunId>` and MCP `amicus_abort` work on council runs: mark `run.json`
  aborted + cascade to the active wave/solo taskIds recorded in it.

### Exit codes and degradation

| Condition | Behavior | Exit |
|---|---|---|
| All stages complete, chair verdict parsed | full run | 0 |
| <2 completed Stage-1 reviews | stop; error doc `council_quorum` | 1 |
| ≥2 reviews but <2 completed judges | proceed; tally `judged:false` | 2 |
| Chair fails (1 retry + 1 fallback promotion) | `verdict.json` written, `overallVerdict:null` | 2 |
| Chair output missing `VERDICT:` line after 1 repair | keep chair prose, `overallVerdict:null` | 2 |
| Cost ceiling hit after tally exists | write verdict (no chair), `overallVerdict:null` | 2 |
| Cost ceiling hit before tally | stop; error doc `cost_exceeded` | 1 |
| Aborted | `run.json` status `aborted` | 130/143 |

Chair fallback promotion order: retry same chair once → highest peers-only street-cred
model from `council stats` that is not a bench seat → give up (no Claude fallback headless).

### Run directory (durable state; skill-compatible layout)

```
council-<runId>/
  briefing-stage1.md          # composed seat briefing (from the user briefing + templates)
  review-<model>.md × N       # Stage-1 outputs (materialized from wave legs)
  bundle-stage2.md            # anonymized judge bundle (identical for all judges)
  judge-<model>.md × N        # Stage-2 raw outputs
  chair-packet.md             # de-anonymized chair packet (+ verdict-scale addendum)
  chair-output.md             # chair raw output
  tally-input.json            # the assembled five-keys object (auditability)
  tally.json                  # engine tally record (council family v2)
  verdict.json                # undecided verdict (tiers + overallVerdict)
  report.html                 # deterministic renderer output
  run.json                    # manifest: {schemaVersion:2, type:'council-run', runId,
                              #  status, stages:[{name,status,startedAt,completedAt,waveId?,
                              #  taskIds?}], bench, chair, critic?, lenses?, labelMap,
                              #  options, usage, exitCode?}
  _scratch/                   # cwd for judge legs (isolation)
```

A pointer file `council-<runId>.json` (`{runDir}`) is written to the project sessions dir so
`status`/`wait`/`list`/`abort` can resolve council runIds without knowing `--out-dir`.

## 5. Engine architecture

New modules, all under the 300-line gate, DI-injected launchers (repo pattern):

| Module | Responsibility |
|---|---|
| `src/council/run.js` | Stage state machine: sequencing, checkpointing to `run.json` after every stage, degradation mapping, cost-gate checks, signal finalization |
| `src/council/briefings.js` | Pure template builders: Stage-1 seat briefing (mandatory anti-sycophancy clause), critic brief, lens briefs, Stage-2 judge bundle preamble (no-tools), chair packet + verdict-scale addendum, bounded repair re-prompts. Templates adapted from `skills/second-opinion/SEAT-BRIEFS.md` with **stricter headless output contracts** (below) |
| `src/council/anonymize.js` | Pure: label assignment (`Review A`…), label↔model map, local→run-global finding-id rewrite (`A1`, `B2`), de-anonymization for the chair packet |
| `src/council/parse-stage2.js` | Last-JSON-block extraction (shared util with `findings.js`) + shape validation for judge output; chair `VERDICT:` line parse; tri-state result per leg |
| `src/council/run-state.js` | Atomic `run.json` read/write (writeFileAtomic), checkpoint model, pointer-file management |
| `src/council/run-launch.js` | Council-flavored wrappers over `fanout()` (Stages 1–2) and headless solos (critic/lens Stage-1 legs, the chair, repair re-prompts): `--no-context`, **`--agent Plan` default** (fixes the skill-vs-engine `build` default mismatch, fanout.js:184), `_scratch` cwd for judges, review-file materialization from leg summaries |
| `src/cli-handlers-council-run.js` | CLI handler (existing `cli-handlers-council.js` is near the line gate) |

Existing primitives consumed unchanged: `validateFindings` (findings.js), `tally()` (tally.js;
lenses force the no-ledger path exactly as the skill mandates; `meta.runType:'headless'`),
`buildVerdict()`/`writeVerdictAtomic` (verdict.js), `report.js`/`report-html.js`, ledger.

### Stage-2 headless output contract (embedded in the judge bundle)

Each judge must end with a trailing JSON block:

```json
{
  "ranking": ["Review B", "Review A", "Review C"],
  "adjudications": [
    {"id": "A1", "verdict": "agree"},
    {"id": "B2", "verdict": "dispute"}
  ]
}
```

- `ranking` uses anonymized labels; the engine maps labels→models via the private map to
  build tally `rankings[].order` (model ids). Ties: nested arrays, per tally's contract.
- `adjudications` use run-global finding ids; verdict enum `agree|dispute|neutral`; the
  engine adds `judge` and includes every judge's vote on every finding (tally excludes
  raiser self-votes itself — do not pre-filter, tally.js:95).
- Malformed/missing block → up to **2 repair re-prompts** (solo, quoting the errors — same
  pattern as `council validate` repair); still bad → that judge is dropped from rankings
  and adjudications and recorded `conformance:'unstructured'` in `runStats`.

### Chair output contract

Chair packet mandates a final `VERDICT: Ship it | Fix these first | Fundamental rethink`
line plus 3–5 hard questions. Parse: last matching `VERDICT:` line wins. Missing → one
repair re-prompt → else `overallVerdict:null` (prose still saved). `verdict.json` (council
family v2) gains **`overallVerdict`** (nullable enum) and **`chair`** is already present.

### runStats and meta population

The engine fills `runStats[]` from leg metadata: `model`, `role` (`seat`, `critic`,
`lens:<slug>`), `wasChair`, `conformance` (from validate/parse results), `status`,
`durationMs`, `usage` — the fields the ledger and street-cred math already consume.

Five-keys `meta` in headless runs is pinned: `claudeInCouncil:false` always;
`meta.models` = the bench seats exactly (critic included — it reviews; **chair excluded**
— it reviews nothing and must not enter the street-cred universe); `runType:'headless'`.

## 6. Anonymization & security model

- The label↔model map exists only in orchestrator memory and `run.json` — never in any
  briefing or judge-visible file.
- Judge legs run with cwd pinned to `<runDir>/_scratch/` + the no-tools preamble, so a
  tool-capable judge cannot read the de-anonymized `review-*.md` files (skill §5.1 parity).
- The chair packet de-anonymizes by design (chair sees identities).
- `run.json` holding the map is acceptable: it is orchestrator-private state at the same
  trust level as the review files beside it.

## 7. Envelope & published schemas

### Convention

Every emitted JSON doc carries `{schemaVersion, type}`. Two families remain:

| Family | Version | Types |
|---|---|---|
| result (`result-schema.js` et al.) | 2 (unchanged) | `run`, `wave`, `abort`, `error`, `spend`, `model-catalog`, `alias-audit`, `doctor` |
| council (`src/council/*`) | **1 → 2** | `council-tally`, `council-verdict`, `council-stats`, `council-validate`, `council-run` |

- Additive field injection only — no re-nesting; existing key-readers keep working.
- `council stats --json`: bare array → `{schemaVersion:2, type:'council-stats', models:[…]}`
  (**the one breaking shape**; Migration note).
- `council validate --json` gains `{schemaVersion, type}` (additive).
- `verdict.json` v2 adds `overallVerdict` (nullable) — additive.
- CLI `status --json` gains `schemaVersion` (additive; it already carries `type`).
- MCP success returns get `schemaVersion` + `type` injected additively.
- Ledger JSONL stays internal at v1 (documented exclusion, not an emitted doc).

### Failure paths routed through the envelope

Fix these bypass sites to `failJson`/`buildErrorDoc` (stdout under `--json`, exit code per
existing error-doc semantics):

- `src/utils/start-helpers.js:68-73` (no model configured — currently plain stderr even
  under `--json`), `:99-111` (selection cancelled), `:114-123` (route error emitted as
  `toStructuredError` on **stderr** — becomes `buildErrorDoc` on **stdout**).
- `src/cli-handlers-status.js:53-59` (missing/invalid taskId — gains a `--json` branch).
- MCP `src/mcp-server.js:249, 282, 874` (validation/route errors — become error-doc-shaped
  `{schemaVersion, type:'error', …}` tool text).

Human-mode (`console.error` without `--json`) behavior is unchanged everywhere.

### Publishing

- `schemas/` at repo root, JSON Schema draft 2020-12, one file per doc type (13 files:
  8 result-family + 5 council-family), shipped in the npm tarball (`files` entry) and
  linked from `docs/schemas.md` (new) + README.
- Tests validate **every builder's real output** against its schema with `ajv` as a
  **devDependency only** — zero runtime deps added.

## 8. MCP surface

- **`amicus_council_run`** (new; 15th default tool): inputs `{briefingFile, models |
  council, chair?, critic?, lenses?, outDir?, maxCost?, timeoutMinutes?, gateway?}`;
  writes the briefing pattern like `amicus_fanout` (briefing-via-file); returns
  `{runId, runDir}` immediately (async). Handler in a new `src/mcp-council-run.js` wired
  from `mcp-server.js` (which stays grandfathered, no extraction taken on).
- **`amicus_status` / `amicus_wait` / `amicus_list` / `amicus_abort`** accept council
  runIds via the sessions-dir pointer file: status reports stage progression + underlying
  wave/leg counts (one hierarchy level above wave→legs); wait registers council runs in
  the in-process registry like other runs. **No new status tool** — tool count discipline
  (52→13 de-bloat) holds; total goes 14 → 15.
- **Fencing (closes H9):** `amicus_council_tally` (`mcp-server.js:1081`),
  `amicus_council_stats` (`:1088`), `amicus_verdict` (`:1095`), and `amicus_council_run`
  wrap their JSON text in `fenceSidecarOutput` — the proven `amicus_read` pattern; JSON
  intact inside the fence; single mechanism, no new sanitizer. CLI `--json` stays
  byte-identical as the programmatic channel. `untrusted-fence.js`'s module doc (which
  currently **excludes** these tools) is updated to match, and SKILL.md's Cowork-mode
  transport note gets one line (fence now present on council tool returns).

## 10. Council Review GitHub Action v2

`council-review.yml` rewritten in place. Carries forward unchanged: string-safe label gate,
fork secret soft-skip, **no checkout of PR code**, concurrency group, and the byte-identical
`neutralize()` sed rules on any model text entering comments (the workflow-test sed-harvest
invariant still holds).

New behavior:

- Briefing: PR diff + title/body (existing capped build) with the council framing.
- Run: `amicus council run --models "$MODELS" --chair "$CHAIR" --prompt-file briefing.md
  --json --max-cost "$MAX_COST" --timeout 10` (exit 0 and 2 both proceed; else fail).
- **Check run** "Council Review" via `gh api`: Confirmed findings → annotations
  (best-effort `file:line` parse from finding `location`, 50-per-request chunking,
  file-level fallback, overflow listed in check summary). Conclusion mapping:
  `fail_on=none` → `success` always; `fix` → `failure` unless `overallVerdict == 'Ship it'`;
  `rethink` → `failure` only on `'Fundamental rethink'`; `overallVerdict:null` → `neutral`.
  Permissions add `checks: write`.
- **Sticky comment v2:** chair `VERDICT:` line, tier table (`tierCounts`), Confirmed list,
  Contested/Disputed/Singleton collapsibles, street-cred table, cost line
  (`usage.cost.amount/source`), artifact link. All model text neutralized.
- **Evidence artifact:** the full run dir via `actions/upload-artifact` (reviews, bundle,
  judge outputs, tally, verdict, report.html, run.json).
- Inputs: add `chair` (default `deepseek`), `critic` (optional), `fail_on`
  (`none|fix|rethink`, default `none`); `max_cost` default `1.00` → `2.00` (council ≈ 2
  waves + chair + repairs vs v1's wave + synth). Secrets unchanged
  (`OPENROUTER_API_KEY`).
