> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `--thinking <level>` reaches the engine — as the prompt field it actually reads (`variant`), never the `reasoning` object that was a silent no-op on every run since the flag existed (probe F1) — and it reaches it TRUTHFULLY: a level the engine does not declare for the model is refused before any request (it would be a silent no-op the engine still echoes on the artifact, F3/M7); a level whose thinking budget the engine would add on top of `outputBudget` on the direct Anthropic route is refused with the exact reservation it would have made (M2) and three remedies; a model the engine's catalogue does not know yet is given a bounded wait for the startup refresh (M0 vs M12) and then sent the level marked *unverified*; every leg document, ledger row and solo metadata records the level that was SENT, not a default nobody sent. The static per-model thinking table and its "use medium instead" adjustment go. Two records this PR's measurements falsified are corrected (the direct `openai` provider carries no output reservation at all, M5/M13/M22), the doctor row says so, and the probe's runtime-config-update measurement — inert for what the engine serves, and it writes a `config.json` into the engine's cwd — is filed with the exact pre-spawn fit (M17) as a follow-up.

**Architecture:** One new pure-plus-one-reader module, `src/utils/engine-variants.js`, owns the decision (`checkVariant`) and the read (`readModelDeclaration` → `/config/providers` `variants` + `limit`, waiting up to 5 s for the engine's startup refresh). `opencode-client.js :: sendPrompt` — the ONE door every sender uses (solo headless, fanout legs, the interactive first prompt, the probe's `viaAmicus` rows) — calls both when `options.variant` is set, throws a typed `VariantRefusedError` before any request, and decorates the SDK result with `sentVariant` the way it already decorates it with `providerError`. `headless.js` turns a refusal into the leg's named death through the channel every other death uses (`sessionError` → `result.error` → metadata reason → the dead-leg note), with the poll loop skipped and zero spend, and returns `variant` / `variantUnverified` emit-when-sent; `interactive.js` returns it as a setup failure as it does for any; `fanout.js` / `start.js` pass `thinking` through as `variant`. `variant` rides the leg patch, the run document (`run.schema.json`), the ledger row and the solo ledger writers exactly the way `finish` did in PR 3. The fit rule keys on the variant entry's shape (`thinking: {type: 'enabled', budgetTokens: N}`), the budget the engine was spawned with (the server handle's `outputBudget`, PR 3) and the engine's own ceiling from the same dump.

### The rules those rows establish

1. **`variant` is the effort lever; `reasoning` never was** (F1/F2, M1, M12). The SDK types carry neither; the body property goes out as-is.
2. **A variant the model does not declare is a silent no-op that the engine still echoes** (F3 on a known model, M7 on a model with `variants {}`). The artifact lies unless amicus refuses first.
3. **The engine's catalogue is the declaration, and it can be late.** A model newer than the bundle reads `limit 0/0, variants {}` until the startup refresh lands (M0) and is known within 36 ms on another run (M12). A read that finds the model unknown must wait, bounded, before deciding; a model still unknown after the wait cannot be validated at all (a custom/local model, or a refresh that never lands).
4. **A variant moves the reservation on exactly one shape**: `thinking: {type: 'enabled', budgetTokens: N}` on the direct Anthropic route adds N on top (M2, K2/K11) and the sum is clamped to the model's ceiling (K3/K4/K10). OpenRouter (M1, M9), direct Google (M15), direct DeepSeek (M16) and an adaptive Anthropic variant (M10b) leave the budget in force.
5. **N is the engine's, not a formula amicus can run**: opus-4-5 declares 16000 for low, medium and high and no max (M0); haiku declares 16000/31999. Only the post-spawn dump knows N.
6. **Nothing changes a descriptor after the spawn.** `PATCH /config` is accepted, changes neither what the engine serves nor what it reports, and writes a merged `config.json` into the engine's cwd — on a user's machine, their project root (M3/M4/M11). It is not a lever amicus may pull. The exact fit — descriptor = budget − N — is proven on the wire (M17: 24000) and needs N before the spawn, so it is a respawn design; filed.
7. **The direct `openai` provider carries no output reservation at all** (M5/M13/M22: the Responses body has no `max_output_tokens`, with or without a descriptor and the flag, for gpt-5.6-terra and gpt-4o alike) and the engine sends `reasoning.effort medium` there by itself when no variant is given (M13). Every sentence that says a budget clamps that route is false.
8. **The vocabulary the curated routes declare between them** is `none, minimal, low, medium, high, xhigh, max` (M0). `none` is real (gpt-5.6, grok, mistral, inkling); `max` is real (kimi, deepseek-v4-flash, gpt-5.6, opus/sonnet/fable-5, haiku, inkling) and amicus has never accepted it; the shipped static table's claims (gpt-5 without `minimal`; gemini with everything) are contradicted by the dump — **corrected, council #235 r1 wave 2:** the dump CONFIRMS the gpt-5 claim (no gpt-5 route declares `minimal`) and contradicts only the gemini one (gemini-3.6-flash declares neither `none` nor `xhigh`). The table is still a guess, and being right on one row is not a declaration; but this line, the CHANGELOG bullet and the `thinking-validators.js` docblock all cited the CONFIRMING row as the contradiction.

### Rulings (decisions this plan makes; each reversible in one line)

- **R1 — amicus sends `variant` and never `reasoning`.** The CLI/MCP/pack surface stays `--thinking` / `thinking`; the internal option is `variant` everywhere from the callers down to `sendPrompt`. `sendPrompt` ignores a `reasoning` option (it forwarded a field the engine never read). Cost if wrong: one property name.
- **R2 — the check lives in `sendPrompt`, the one door.** When `options.variant` is set, `sendPrompt` reads the model's declaration (waiting up to 5 s, polling every 250 ms, for the catalogue to know the model), decides, and either throws `VariantRefusedError` BEFORE the request or sends `body.variant` and decorates the result with `sentVariant: {variant, verified, waitedMs}`. A leg record derives `variant` / `variantUnverified` from that. Two senders (headless, interactive) plus the probe's `viaAmicus` rows go through it; no second validation site exists. Cost if wrong: one call site.
- **R3 — three outcomes, in this order:** (a) the model is unknown after the wait (`limit.context` 0, no variants) → SEND, `verified: false`, a `logger.warn` with the wait, `variantUnverified: true` on the leg record; (b) known, level undeclared → REFUSE `VARIANT_UNDECLARED` naming the declared set (or "no variants at all"); (c) known and declared → the fit check, then SEND `verified: true`. The refusal for (b) replaces the old "use medium instead" adjustment: a level the user did not ask for is never sent. Cost if wrong: `checkVariant`'s branch order.
- **R4 — the fit check REFUSES rather than fits.** With a budget set (`options.outputBudget` is a positive integer — the handle's spawn value; `null` = unset, omitted = unknown), a declared entry of the shape `thinking: {type: 'enabled', budgetTokens: N > 0}` on a model whose dump ceiling C exceeds the budget B is refused `VARIANT_OVER_BUDGET` with the reservation `min(B + N, C)` the leg would make and three remedies (raise the budget to ≥ C — K4; route through OpenRouter — M9; an adaptive-thinking model — M10b). With no budget, or an unknown one, or B ≥ C, or any other entry shape: no fit check (the engine's native behaviour: 32000 + N, H3/H4; or the sum clamped to C, K4). The shape is keyed on, not the provider id, so an unmeasured provider carrying the same shape refuses loudly rather than overshooting silently; the message says "on this route" and cites M2/K2. The BACKLOG C1 item is closed as "refused, with the numbers"; the exact pre-spawn fit (M17) is filed with the measured obstacles (rules 5 and 6). Cost if wrong: one `if` in `checkVariant`.
- **R5 — a refusal is a leg death with zero spend through the existing channel.** `headless.js` catches the typed error at the send, seeds `sessionError` with its message, skips the poll loop (as the pre-send backstop path does), and returns the standard error shape (no `finish`, zero usage) so every terminal write (progress, metadata, the dead-leg note, the ledger row) happens as for any other death; `interactive.js` returns `Session setup failed: <message>` through its existing catch; a fanout leg becomes an `error` leg document failing only itself; a council never sends a variant (R6). `start --no-ui` exits 1 with the reason; `--json` carries it in `error`. Cost if wrong: one branch in the send catch.

/**
 * @module engine-variants
 * #218 PR 4: the effort lever. The engine's prompt endpoint selects reasoning
 * effort through `variant: string` (probe F2); the `reasoning` object amicus sent
 * for every `--thinking` until now was never a prompt field and reached nothing
 * (F1). A variant the model does not DECLARE is a silent no-op that the engine
 * still echoes on the assistant message (F3 on a known model, M7 on one with
 * `variants {}`), so a run's own artifact can claim an effort the wire never
 * saw. This module is the one place amicus asks the engine what a model declares
 * (`/config/providers` -> `variants` + `limit`, M0) and decides, per leg, to send,
 * refuse, or send unverified.
 *
 * Measured, engine 1.18.15 (BACKLOG "v4.9.4 records", the PR 4 table):
 *   - a model newer than the engine's bundled catalogue reads `limit 0/0,
 *     variants {}` until the startup models.dev refresh lands (M0: qwen3.8-max-0902,
 *     glm-5.3 on a cold engine) and is known within 36 ms on another run (M12) —
 *     so a read that finds the model unknown WAITS, bounded, before deciding;
 *   - a variant does not move the reservation on OpenRouter (M1, M9), direct
 *     Google (M15), direct DeepSeek (M16) or an adaptive-thinking Anthropic model
 *     (M10b); only an entry shaped `thinking: {type: 'enabled', budgetTokens: N}`
 *     adds N ON TOP of the reservation (M2: 24000 + 16000 = 40000; K2/K11),
 *     clamped to the model's ceiling (K3/K4/K10);
 *   - N is the engine's, not a formula of the ceiling (M0: opus-4-5 declares
 *     16000 for low, medium AND high, and no max), so the post-spawn dump is the
 *     only source of N — and nothing changes a descriptor after the spawn: a
 *     runtime PATCH /config changes nothing the engine serves and writes a
 *     config.json into its cwd (M3/M4/M11). The exact pre-spawn fit (descriptor
 *     = budget − N, proven M17) is filed, not built; this module REFUSES the
 *     over-budget shape with the numbers instead (BACKLOG C1's second clause).
 */
'use strict';

const { positiveCount } = require('./model-output-limit');

/** Every level the curated routes declare between them (M0), in effort order. */
const VARIANT_LEVELS = ['none', 'minimal', 'low', 'medium', 'high', 'xhigh', 'max'];

/** How long a read waits for the engine's startup refresh to make a model known (M12: 36 ms). */
const DECLARATION_WAIT_MS = 5000;
const DECLARATION_POLL_MS = 250;

/** Thrown by opencode-client.js :: sendPrompt BEFORE any request when a variant is refused. */
class VariantRefusedError extends Error {
  constructor(code, message) {
    super(message);
    this.name = 'VariantRefusedError';
    this.code = code;
  }
}

/**
 * One read of `/config/providers` for one model. `known` is `limit.context > 0`:
 * a model amicus registered that the engine's catalogue lacks reads 0/0 (J1, M0);
 * a provider or model missing from the dump altogether is unknown too.
 * @returns {Promise<{known: boolean, variants: object, ceiling: number|null}>}
 */
async function readDeclarationOnce(client, providerID, modelID) {
  const r = await client.config.providers();
  const list = (r && r.data && Array.isArray(r.data.providers)) ? r.data.providers : [];
  const p = list.find((x) => x && x.id === providerID);
  const m = (p && p.models && Object.prototype.hasOwnProperty.call(p.models, modelID)) ? p.models[modelID] : null;
  const limit = (m && m.limit && typeof m.limit === 'object') ? m.limit : {};
  return {
    known: positiveCount(limit.context) !== null,
    variants: (m && m.variants && typeof m.variants === 'object') ? m.variants : {},
    ceiling: positiveCount(limit.output),
  };
}

/**
 * The engine's declaration for `model` ('provider/model', split at the FIRST
 * slash — an OpenRouter id keeps its vendor path), waiting up to `waitMs` for
 * the catalogue to know it. Named mutant "NOWAIT" (tests/utils/engine-variants.test.js).
 * @param {object} client SDK client
 * @param {string} model executable id
 * @param {{waitMs?: number, pollMs?: number, sleep?: Function, now?: Function}} [opts] test seams
 * @returns {Promise<{known: boolean, variants: object, ceiling: number|null, waitedMs: number}>}
 */
async function readModelDeclaration(client, model, opts = {}) {
  const idx = typeof model === 'string' ? model.indexOf('/') : -1;
  const providerID = idx > 0 ? model.slice(0, idx) : String(model);
  const modelID = idx > 0 ? model.slice(idx + 1) : '';
  const waitMs = opts.waitMs === undefined ? DECLARATION_WAIT_MS : opts.waitMs;
  const pollMs = opts.pollMs === undefined ? DECLARATION_POLL_MS : opts.pollMs;
  const sleep = opts.sleep || ((ms) => new Promise((resolve) => setTimeout(resolve, ms)));
  const now = opts.now || Date.now;
  const start = now();
  let d = await readDeclarationOnce(client, providerID, modelID);
  while (!d.known && now() - start < waitMs) {
    await sleep(pollMs);
    d = await readDeclarationOnce(client, providerID, modelID);
  }
  return { ...d, waitedMs: now() - start };
}

/**
 * Pure: send, refuse, or send unverified — in that order of tests.
 *   1. unknown model -> {ok: true, verified: false} (mutant "UNKNOWNREFUSED");
 *   2. known, undeclared -> VARIANT_UNDECLARED naming the declared set
 *      (own properties only — mutant "PROTOLOOKUP");
 *   3. declared, entry `thinking: {type: 'enabled', budgetTokens: N}`, a positive
 *      budget B below the ceiling C -> VARIANT_OVER_BUDGET with min(B + N, C)
 *      (mutants "ALWAYSREFUSE": drop `B < C`; "FITWITHOUTBUDGET": default a null
 *      budget to 32000; "ANTHROPICONLY": key on the provider id instead of the shape);
 *   4. otherwise {ok: true, verified: true, entry}.
 * @param {{variant: string, model: string, declaration: object, outputBudget?: number|null}} a
 * @returns {{ok: true, verified: boolean, entry?: object} | {ok: false, code: string, reason: string}}
 */
function checkVariant({ variant, model, declaration, outputBudget }) {
  if (!declaration || !declaration.known) { return { ok: true, verified: false }; }
  const variants = (declaration.variants && typeof declaration.variants === 'object') ? declaration.variants : {};
  if (!Object.prototype.hasOwnProperty.call(variants, variant)) {
    const names = Object.keys(variants);
    const listed = names.length > 0 ? names.join(', ') : 'no variants at all';
    return { ok: false, code: 'VARIANT_UNDECLARED', reason: `VARIANT_UNDECLARED: ${model} does not declare a '${variant}' variant — the engine's catalogue lists ${listed} for it (/config/providers); an undeclared variant is a silent no-op on the wire (probe F3/M7), so nothing was sent. Pick one of the listed levels, or omit --thinking to run at the provider's own default effort` };
  }
  const entry = variants[variant];
  const thinking = (entry && entry.thinking && typeof entry.thinking === 'object') ? entry.thinking : null;
  const budgetTokens = (thinking && thinking.type === 'enabled') ? positiveCount(thinking.budgetTokens) : null;
  const budget = positiveCount(outputBudget);
  const ceiling = declaration.ceiling;
  if (budgetTokens !== null && budget !== null && ceiling !== null && budget < ceiling) {
    const sum = budget + budgetTokens;
    const reservation = Math.min(sum, ceiling);
    const how = sum > ceiling ? `${budget} + ${budgetTokens}, clamped to the model's ${ceiling} ceiling` : `${budget} + ${budgetTokens}`;
    return { ok: false, code: 'VARIANT_OVER_BUDGET', reason: `VARIANT_OVER_BUDGET: the '${variant}' variant on ${model} carries a ${budgetTokens}-token thinking budget that the engine adds ON TOP of the reservation on this route (probe M2: 24000 + 16000 = 40000; K2), so with outputBudget ${budget} this leg would reserve ${reservation} (${how}) — ${reservation - budget} over the budget; nothing was sent.   }
  return { ok: true, verified: true, entry };
}

}
